# fab-07/09 单点数据与板块表现的查库纪律

> 状态：方案待拍板（未动代码）｜改进前数据可信度：高（baseline-v2）

## 1. 问题与现状

两类"看起来随口一问"的数据问题，模型有相当概率**不查库直接作答**：

- "最近哪些行业板块表现最好？推荐几个"（fab-07）：2/4 的 run 零工具调用，直接给印象性推荐；
- "五粮液2025年3月5日的换手率"（fab-09）：2/4 的 run 没调 `read_factor_data`，凭记忆给出换手率。

现状源头：提示词的总规则"只能引用工具返回的数据，严禁编造"（`langgraph-agent.service.ts:1304`）是**否定式**约束——它没告诉模型"这类问题必须先查库"；对"板块表现"这种没有现成单表可查的问题，模型连"该用哪个工具"都不确定，于是滑向印象作答。

## 2. 改进前数据（v3 定稿）

- fab-07：**3/4**（v2 曾 2/4），失败 run 零工具调用直接给印象性推荐
- fab-09：**2/4**，未调 `read_factor_data` 凭记忆给换手率
- 对照组（说明不是普遍性失能）：fab-04（茅台收盘价）4/4 查库、fab-03（银行股数量）4/4 筛池——**具体个股+具体日期的问法纪律好，模糊/ impression 型问法纪律差**

## 3. 改进方案

在回复规则区"查询无数据行时如实告知"（:1357）之前插入一条（+约 80 字）：

> 个股/指数的任何具体数值（价格、换手率、涨跌幅、估值）与板块/行业的表现结论，必须先经 `read_factor_data` 或 `screen_stock_pool` 查库再回答；"最近表现""推荐"类问题也一律先查数，没有对应数据就如实说明，禁止凭印象给结论。

- **预期**：fab-07、fab-09 → 4/4 或至少 3/4
- **代价**：+80 字
- **风险**：与 fab-01 的"如实说明+替代"条款（另案）方向一致、互相增强；需盯 fab-04/05（本来就守规矩的）有无被过度措辞拖慢
