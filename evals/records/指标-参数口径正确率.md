# 指标：参数口径正确率

> 基线 v1：**90.0%**（pass^4 80%）｜口径类 20 任务 run 级：模型原始工具调用参数 + 引擎实参检查全部通过的比例

## 1. 定义与构成

断言点 = confirmedCalls 原始入参（entryFilters / sortFactors / industries / weightFn / executionTiming 等）与 mock 引擎实收参数——不看回复文案（防"长引信"式失败：引擎照跑、结果看似合理、文案看不出错）。

拖累任务（基线中口径检查未全过的）：cal-13（补测 run 级 25%）、cal-16（0/4）。其余 18 项口径任务基线全过或仅个位 run 抖动。

## 2. 提高方案

### 方案一：择时规则方向语义显式化（模块：大盘择时｜靶子 cal-13）

- **现状**：rules 的引擎语义是"由熊转牛的入场条件"（timing.ts），提示词（:1312-1316）与 schema 均未点明方向。模型把"跌破3000点空仓"按字面写成 `< 3000`（引擎语义下是反策略），方向翻转率约 40%（8 run：5 对 3 错）。
- **改法**（+55 字）：择时规则行追加——"rules 是'由熊转牛'的入场条件（满足→满仓，不满足→bearPositionPct）：用户说'跌破X空仓'应写 `field > X`（即站上X满仓），不要按字面写 `<`。"
- **预期**：cal-13 → 4/4。

### 方案二：不卖条件与卖出规则并存提醒（模块：卖出与持有规则｜靶子 cal-16）

- **现状**：keepRules 规则行（:1321-1322）独立成条；"两组都要传"句式只存在于 entryFilters/sortFactors（:1311）。基线 0/4，keepRules 稳定缺席。
- **改法**（+60 字）：keepRules 行追加——"用户同时表达卖出条件（如止损/止盈）与不卖条件时，`sellRules` 与 `keepRules` 两处都要传。"
- **预期**：cal-16 → 4/4。

**合计代价**：+115 字（当前 system prompt ≈3.6k 字，+3%）。
