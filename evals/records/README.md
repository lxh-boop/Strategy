# 改进项记录（records/）

**一个需要改进的地方 = 一个文档**，文档内自含该事项的完整链路：
`1 问题与现状（带 file:line）→ 2 改进前数据 → 3 改进方案（待拍板，含代价与风险）→ 4 改进后数据（待填）→ 5 取舍与结论（待填）`。

共享的背景（被评对象快照、总体基线、噪声纪律）在 [000-方法快照与基线.md](000-方法快照与基线.md)，各文档不重复。

## 判定规则（每个文档第 5 节用）

1. **同口径对比**：改进前后同 k、同任务集、同 judge 档位。
2. **纯增量**：目标任务 pass^4 上升，且同类别其余任务与分类别指标不降（单任务 ±1 run、分类别 ±10% 内算噪声）；超出噪声带的下降 = 有弃有立，必须写明"弃了什么、为什么可接受"，写不清默认不可接受。
3. **提示词类改动统一核算长度代价**（system prompt 每变长一分，全部任务分摊一分 token 与注意力）。
4. **采纳动作**：提示词改动单独 commit，结论回写文档第 5 节并更新下方索引。
