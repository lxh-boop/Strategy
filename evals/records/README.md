# 改进项记录（records/）

按**测评指标**组织：一个指标一份档案，它就是该数据的台账——当前值、拖累任务、提高方案（含落点模块与技术细节）、每轮复测的趋势表。**之后的改进 = 提高这些数据**：每条方案标注它服务的指标，复测后把新值写回趋势行，是否采纳看指标是否如期上移且其他指标不跌。

共享背景（方法快照、基线细节、噪声纪律）在 [000-方法快照与基线](000-方法快照与基线.md)。

## 判定规则（各指标档案的趋势行与结论用）

1. **同口径对比**：改进前后同 k、同任务集、同 judge 档位；
2. **纯增量**：目标指标上移且其他指标不跌（单任务 ±1 run、分类别 ±10% 内算噪声；成本超预算线即视为跌）；超出噪声带的下降 = 有弃有立，必须写明"弃了什么、为什么可接受"；
3. **落点标注**：每条方案标注落点模块（大盘择时/卖出持有/参数澄清/防编造/确认门）——同模块方案合批复测时按失败要点归因；
4. **采纳动作**：提示词改动单独 commit，新值回写指标趋势行并更新总览表。

> 指标档案随测评体系演进追加（如二期在线层的"端到端任务完成率"）；已放弃的方案保留在指标档案内不删——状态列标"已放弃（原因）"。
