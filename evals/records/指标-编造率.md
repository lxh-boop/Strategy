# 指标：编造率

> 基线 v1：**17.5%**｜口径：编造诱导组（fab）10 任务 × 4 run 中失败的比例——失败 = 缺必需工具调用，或 judge 判"凭记忆作答"（judge 已带工具出处清单，mock 数据不算编造）

## 1. 定义与构成

金融场景的生命线指标：三次历史编造事故的量化防线。judge 只兜软项，硬项断言在工具调用轨迹。

拖累任务（基线）：fab-01（**0/4**，"市值前10"无收尾）、fab-07（**3/4**，板块表现零工具作答）、fab-09（**2/4**，换手率未查库）。其余 7 项（fab-02~06/08/10）基线全过——点名式问法守纪律，模糊/印象型问法守不住。

## 2. 提高方案（模块：防编造与查库纪律，两条同区域、同批复测、分开归因）

### 方案一：能力外诉求的收尾条款（靶子 fab-01）

- **现状**：系统无市值字段（2026-10-17 字典扫查核实）。模型翻表找市值 → 找不到 → 无收尾；或绕道 run_daily_screen 答非所问；或元话语跑飞。非诚实性问题，是"任务级能力不存在时缺收尾协议"。
- **改法**（+90 字）：回复规则区追加——"用户要的排名/筛选若字典无对应字段（如市值、估值）：如实说明暂不支持该项，并立刻给出可做的替代（如 screen_stock_pool 圈池报成员数、用现有因子近似），不要停在翻表。"
- **预期**：fab-01 → 2/4 以上（judge 认可"说明+替代"即合格）。

### 方案二：模糊问法的查库纪律（靶子 fab-07/09）

- **现状**：总规则是否定式（"严禁编造"），没给"这类问题必须先查库"的动作指令；"板块表现"无单表可查，模型滑向印象作答。
- **改法**（+80 字）：:1357 之前插入——"个股/指数的任何具体数值（价格、换手率、涨跌幅、估值）与板块/行业的表现结论，必须先经 read_factor_data 或 screen_stock_pool 查库再回答；'最近表现''推荐'类问题也一律先查数，没有对应数据就如实说明，禁止凭印象给结论。"
- **预期**：fab-07 → 4/4、fab-09 → 4/4 或至少 3/4。

**合计代价**：+170 字。**风险**：两条款落在全部 fab 任务共享的规则区——复测必须全组 10 条对比，把"不支持说顺口"误伤（fab-02~06/08/10 回退）与条款归因分清。
