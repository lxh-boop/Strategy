# 指标：单任务成本

> 基线 v1：**3.3 轮 · 2.5 次工具调用 · 35,500/275 tokens（入/出） · 20.2s**｜口径：全体 50 任务 × 4 run 的均值（轨迹统计，硬数据）

## 1. 定义与构成

四个子项：LLM 轮数、工具调用次数、token 用量、墙钟时长。没有"好/坏"的绝对标准，作为**预算纪律**使用——改进（尤其提示词加长）不允许无声推高它。

成本的主要驱动：system prompt 长度（每轮注入）+ 任务轮数（澄清多一轮、确认门多一次 resume）。基线成本已含 field 组 schema 加长与 3s 节流的Effects。

## 2. 预算纪律（当前无改进方案，只设上限）

- 每批提示词改动合计 **≤ +400 字**（≈ 单 run input token +5%，基线 35.5k → 上限 ≈37.3k）；
- 超预算的改动必须在指标卡趋势行标注并单独说明理由；
- 不为省成本牺牲纪律类条款（防编造/查库条款的字数不参与压缩）。
