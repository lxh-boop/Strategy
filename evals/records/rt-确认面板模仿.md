# rt-面板模仿：确认面板被文本仿写、未实际调工具

> 状态：方案待拍板（未动代码）｜发现于 baseline-v2（rt-10 全部 4 个 run 复现）

## 1. 问题与现状

场景：用户取消一次回测后又发起新回测。模型没有调用 `run_strategy_backtest`，而是**自己输出了一段"将按以下参数执行策略回测：…"的确认面板文案**（模仿历史里 T1 真面板的样子）。后果链：

- `pendingConfirms` 为空、无 `confirm_pending` 进度事件 → **前端不弹结构化确认窗**，用户看到的是一段长得像面板的文本；
- 用户回复"确认"时走普通消息路径 → 模型这时才真正调工具 → **真面板再弹一次 → 用户要确认两次**；
- 安全性未破：真实执行仍然要过真确认门（v2 轨迹实证：假面板 → 用户确认 → 真面板 → 确认后才执行），属 UX 缺陷非安全洞。

现状源头：历史会话里的面板文本作为 agent 气泡注入上下文（`prepareMessages`，langgraph-agent.service.ts:1149-1169），提示词没有"面板由系统生成、不许自己写"的禁令；`run_strategy_backtest` 规则行（:1306-1311）也未强调"必须实际调用工具"。

## 2. 改进前数据

- rt-10（取消后重新发起）：**0/4**，4 个 run 全部在"取消→再发起"段出现面板仿写
- 波及面推断：凡历史里出现过真面板的会话，再次发起回测都有仿写风险（rt-02/rt-04 等在 v2 未复现，因其未被"取消"打断——取消后重发是高发形态）

## 3. 改进方案

回复规则区追加一条（+约 60 字）：

> 确认面板由系统在工具调用后自动生成；发起回测/分析必须实际调用对应工具，严禁自行输出"将按以下参数执行"之类的参数清单文本。

- **预期**：rt-10 类场景 0/4 → 3/4 以上（模型直接调工具 → 真面板一次到位）
- **代价**：+60 字
- **风险**：低——与"最终回复不超过 90 字、不输出 JSON"既有风格一致；复测盯 rt-01~rt-08 有无连带回退
