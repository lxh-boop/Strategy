命令面（全部 O(1)）

命令语法说明
SETSET key value [EX sec]写键。EX 同时设 TTL，原子完成；另有 PX ms 毫秒版、NX（仅不存在时写）、XX（仅存在时写）
GETGET key读键，无则 nil。值是任意字节串（常放 JSON）
DELDEL key [key …]删一个或多个键，返回删除数
EXISTSEXISTS key [key …]存在性检查，返回命中个数（0/1/…）
EXPIREEXPIRE key sec给已有键设/重设 TTL（SET EX 能一步做的不要拆两步）
TTLTTL key剩余秒数。-1 = 键在但无 TTL；-2 = 键不存在。毫秒版 PTTL
PERSISTPERSIST key移除 TTL，变回永生键
TYPETYPE key看键的值类型（string/list/hash/…）
INCR / INCRBYINCR key / INCRBY key nstring 内置整数语义，原子自增（DECR 相反）。计数器/限流器基石
SETEXSETEX key sec value旧写法，等价 SET key value EX sec；新代码统一用后者

键名约定（项目向）

Redis 键空间是扁平的，没有目录——层级全靠约定俗成的冒号分隔。照你的取数场景推荐：

factor:<field>:<securityId>:<yyyymmdd>     # 单点因子读缓存（read_factor_data）
quote:<yyyymmdd>:<ticker>.<exchange>       # 日行情行缓存
backtest:<strategyId>:<hash>               # 策略回测结果缓存
rl:<userId>:<windowStart>                  # 限流计数器（INCR + EX）

机制对照：你的缓存 → Redis

mysql-factor-data.service.ts 里Redis 对应物要点
hit.at 手工 TTL（10 分钟）SET … EX + 服务端过期TTL 记在服务端，进程重启/部署不影响存活中的键
LRU 200 条封顶无内置默认需配 maxmemory + maxmemory-policy allkeys-lru；否则键无限增长到吃满内存
inflight 同 key 并发去重单命令原子性 / SET NX单条命令天然原子；多条命令的组合原子性要 Lua 脚本或 MULTI/EXEC（后续课）
「结果集只读」约定反序列化副本每次 GET 都是新副本，天然无共享可变状态，约定可删
进程重启缓存全丢独立进程存活；可选 RDB/AOF 持久化持久化是双刃剑（后续课），缓存场景也可以接受重启冷启动
缓存命中打日志（cacheHits）INFO stats / MONITOR命中率观测内建在服务端统计里
迁移提醒 对照表第二行是最大的认知差：Redis 不会自动 LRU。你的 200 条封顶在 Redis 语境里是部署配置（maxmemory-policy），不是代码行为。引 Redis 时忘配这一项，是生产事故的经典来源。
