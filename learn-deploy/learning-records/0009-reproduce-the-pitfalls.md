# 无线上事故经验：凡说"踩过的坑"，都要配机制 + 可复现小实验

用户看到 q03 里"这恰恰是考'有没有真踩过 docker stop 卡 10 秒'"后，回问"还是不知道，为什么会卡十秒"。说明两点：① 信号与 PID 1 机制不在用户知识里（q03、q13 的解释分散，且默认读者懂信号）；② 更重要的——课件里"考你有没有踩过"这种说法预设了用户有生产事故经验，而用户没有。已重写 q13：信号是什么 → docker stop 先礼后兵 → 不退出的两个原因（信号没送到 / PID 1 忽略默认动作）→ 三层解法 → 退出码 137 判断 → 两条命令的复现实验。

Evidence: 2026-11-02 用户原话："有没有真踩过 docker stop 卡 10 还是不知道，为什么会卡十秒"。
Implications:
- 面试向课件里凡出现"踩过 / 经典坑 / 线上事故"，必须同时给出机制和一个能在用户电脑上 1 分钟内复现的实验。用户没有事故经验，复现过一次，面试时就能真实地说"我复现过"，把"背的"变成"做过的"。
- 可以考虑建一份"经典坑复现清单"（docker stop 10 秒、json-file 日志撑盘、OOM 137、绑 127.0.0.1 访问不通、depends_on 不等就绪、nginx 413、SSE 被缓冲……）——已向用户提议，等用户决定。
- 待验证：用户能否口述"卡 10 秒 = SIGTERM 没让进程退出（信号没送到或 PID 1 忽略），等满宽限期被 SIGKILL，退出码 137"。
