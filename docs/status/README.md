# 接口与功能实现状态表（项目代办事项）

> 本目录是全项目的**待办清单**：功能模块看 [modules.md](modules.md)（主表），
> 接口明细看 [api.md](api.md) / [svc.md](svc.md) / [b-int.md](b-int.md)。
> 表是给人快速看的，**实现的权威记录永远是 git 提交历史**。

## 状态档位

| 图标 | 含义 |
|---|---|
| ⬜ | 未实现 / 待认领 |
| 🚧 | 进行中 |
| ✅ | 已实现（有对应提交） |
| ➖ | 暂缓（备注原因） |

## 更新规则

1. **认领**：把"负责人"从 `待认领` 改成自己，状态改 🚧，一次小提交；
2. **完成**：状态改 ✅，填完成提交号或日期，一次小提交；功能模块行在其**全部接口**完成后才能标 ✅；
3. **提交规范**：状态变更用 `status(编号): 说明`；功能实现用 `feat(编号): 说明`，
   修复用 `fix(编号): 说明`——编号即接口编号（API-xx / SVC-xx / B-INT-xx）或模块编号（M-xx）；
4. **push 前** `git pull --rebase`（每行只有负责人会改，正常不会冲突）。
5. **备注** 应该写明这个接口依赖哪一个接口，这个模块提供哪一个接口，并且提供的结构需要什么参数；

## 新增功能怎么做（编号追加规则）

1. **取号**：新接口在划分文档 §3 取**预留段的下一个编号**，只追加不复用：
   - HTTP 接口：`API-25` 起顺延；
   - LLM 工具：`TOOL-C03` 起顺延；
   - B 模块内部业务接口：`B-INT-05` 起顺延；
   - 功能模块：`M19` 起顺延；
2. **定义**：在 `docs/模块划分文档.md` §3 加行（说明/入参/出参至少写清功能语义，细节可迭代）；
3. **上表**：状态表加行（接口表 + `modules.md` 功能行），状态 ⬜；
4. 之后走"认领 → 🚧 → ✅"正常流转。
