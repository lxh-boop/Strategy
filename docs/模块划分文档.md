# 因子智投（AlphaSage）模块划分与接口文档

> 本文回答三个问题：项目分为哪几个模块；**每个模块需要哪些接口、提供哪些接口**（全部编号）；
> 仓库里**每个文件/文件夹属于哪个模块**、依赖什么、贡献什么。
> 接口请求/响应的详细字段见 `factor-agent-react/docs/backend-api.md`（契约），编号以本文为准。

---

## 1. 接口与实现分离（架构总则）

**所有后端 service 一律接口与实现分离**。每个领域模块的标准结构：

```
<域>/<域>.controller.ts            # HTTP 接口层：路由 + 入参校验（对前端 A 的契约）
<域>/<域>.service.ts               # 业务接口：abstract class，只写"能做什么"
<域>/dto.ts                        # 入参/出参契约
<域>/implementations/              # 实现：写"怎么做"，可替换
<域>/<域>.module.ts                # 装配：{ provide: 接口, useClass: 实现 }，换实现只改这一行
```

**落点（全部后端组件）**：

| 组件 | 接口 | 实现 |
|---|---|---|
| 存储 | `core/store.service.ts` | `implementations/memory-store.service.ts` |
| 回测 | `core/backtest.service.ts` | `implementations/mock-backtest.service.ts` |
| 筛选 | `core/screen.service.ts` | `implementations/mock-screen.service.ts` |
| 智能体 | `agent/agent.service.ts` | `implementations/langgraph-agent.service.ts` |
| 智谱客户端 | `zhipu/zhipu.service.ts` | `implementations/http-zhipu.service.ts` |
| 会话业务 | `conversations/conversations.service.ts` | `implementations/conversations.service.impl.ts` |
| 策略业务 | `strategies/strategies.service.ts` | `implementations/strategies.service.impl.ts` |
| 市场数据业务 | `market/market.service.ts` | `implementations/market.service.impl.ts` |
| 用户业务 | `user/user.service.ts` | `implementations/user.service.impl.ts` |

新增能力（数据库存储、真实行情回测等）= 在 `implementations/` 下新增实现文件 +
module 改一行 `useClass`，接口编号与上层代码不动。

**前端 A 的对应关系**：`src/api.ts`（接口封装层）+ `src/types.ts`（类型契约）就是前端的
"接口层"，pages/components 是消费方——前端以模块导出为契约，不引入 abstract 类。

## 2. 接口编号规则

| 前缀 | 含义 | 范围 |
|---|---|---|
| `API-xx` | HTTP REST 接口（前端 A ↔ 后端业务层 B） | API-01 ~ API-18 |
| `SVC-Cxx` | C 模块（智能体引擎）对 B 提供的进程内服务接口 | SVC-C01 |
| `TOOL-Cxx` | C 模块注册给大模型（GLM）的工具接口 | TOOL-C01 ~ TOOL-C02 |
| `SVC-Zxx` | zhipu 直连客户端提供的服务接口 | SVC-Z01 ~ SVC-Z03 |
| `SVC-Dxx` | D 模块（核心领域层）提供的进程内服务接口 | SVC-D01 ~ SVC-D21 |
| `B-INT-xx` | B 模块内部业务接口（controller 消费，模块内可见） | B-INT-01 ~ B-INT-04 |
| `C-INT-xx` | C 模块内部接口（模块内可见） | C-INT-01 |
| `EXT-xx` | 外部系统接口 | EXT-01 |

## 3. 接口编号总表

### 3.1 HTTP REST 接口（API-01 ~ API-18，A ↔ B）

| 编号 | 方法 路径 | 说明 |
|---|---|---|
| API-01 | GET `/api/health` | 健康检查：`zhipuConfigured`、`defaultModel` |
| API-02 | GET `/api/conversations` | 会话列表（含全部消息，按更新时间倒序） |
| API-03 | POST `/api/conversations` | 新建会话（后端自动带欢迎语） |
| API-04 | DELETE `/api/conversations/:id` | 删除会话 |
| API-05 | POST `/api/conversations/:id/clear` | 清空会话（保留会话，恢复欢迎语、标题重置） |
| API-06 | GET `/api/conversations/:id/messages` | 拉取历史消息（列表已带全量，留给分页场景） |
| API-07 | POST `/api/conversations/:id/messages` | **发消息（核心链路）**：调智能体，返回 `{userMessage, agentMessage}`，agent 消息可含卡片 |
| API-08 | GET `/api/strategies` | 策略列表（含曲线、指标、持仓） |
| API-09 | POST `/api/strategies` | 创建策略（草稿）；对话卡片"保存为我的策略"也走此接口 |
| API-10 | PATCH `/api/strategies/:id` | 更新配置 = **保存并自动重新回测**，返回更新后完整 Strategy |
| API-11 | POST `/api/strategies/:id/backtest` | 重新回测（可带 period/topK/feeRate，缺省用默认值） |
| API-12 | GET `/api/strategies/:id/report` | 回测报告详情 `{metrics, curve, benchCurve, holdings}` |
| API-13 | DELETE `/api/strategies/:id` | 删除策略 |
| API-14 | GET `/api/factors` | 因子库 9 项 `{id, name, desc}`（UI 数据驱动） |
| API-15 | GET `/api/backtest-params` | 回测参数项 `{label, value, hint}`（UI 自动渲染） |
| API-16 | POST `/api/screen` | 选股筛选 `{universe?, filters[], topN?}` → `{stocks, total}` |
| API-17 | GET `/api/user/profile` | 用户信息 + 因子偏好雷达 + 设置项（模型/数据来源为 readonly 展示） |
| API-18 | PATCH `/api/user/settings` | 更新设置项，仅 notify/report/risk 可配置（toggle 传 `on`、single 传 `value`），其余 key 400 |

通用约定：Base URL `/api`；JSON；错误统一 `{ "error": { "code", "message" } }` + HTTP 状态码；
鉴权预留 `Authorization: Bearer <token>`（当前无登录态）。
数值口径：百分比是 `14.6`（14.6%）不是 0.146；净值曲线起点 100、30 个月频点；
因子权重归一化合计 100（1 位小数，残差补给最大项，合计 0 → 400）。

### 3.2 B 模块内部业务接口（B-INT，controller → service 接口 → 实现）

| 编号 | 接口方法（abstract 契约） | 消费方 | 说明 |
|---|---|---|---|
| B-INT-01 | `ConversationsService`：`list()` / `create()` / `remove(id)` / `clear(id)` / `getMessages(id)` / `sendMessage(id, text)` | conversations.controller | 会话业务：编排"校验 → 拼 routeText → 调 SVC-C01 → 落库 → 命名 → 返回" |
| B-INT-02 | `StrategiesService`：`list()` / `create(input)` / `update(id, patch)` / `backtest(id, params?)` / `getReport(id)` / `remove(id)` | strategies.controller | 策略业务：权重归一化（SVC-D21）、**保存=归一化+自动重新回测**（API-10 语义） |
| B-INT-03 | `MarketService`：`listFactors()` / `listBtParams()` / `screen(options)` | market.controller | 市场数据业务：汇聚 SVC-D14/D15/D20 |
| B-INT-04 | `UserService`：`getProfile()` / `updateSetting(key, payload)` | user.controller | 用户业务：设置项白名单校验（notify/report/risk 之外 400），汇聚 SVC-D17/D18 |

### 3.3 进程内服务接口（跨模块：B ↔ C ↔ D）

| 编号 | 签名 | 提供方 → 消费方 | 说明 |
|---|---|---|---|
| SVC-C01 | `AgentService.reply(conversation, userText, routeText): Promise<AgentReply>` | C → B | 智能体唯一公开方法。入参：完整会话（含 messages，C 自取最近 6 条做上下文）、当前消息、近 2 条+当前消息拼接（规则分支消歧）。出参 `{ text, card? }`：text 为文案（GLM 失败时=失败原因），card 可选 report/backtest/stocks |
| TOOL-C01 | `select_factors(factors[], universe?, rebalance?, name?, tag?)` | C → GLM | LLM 工具：抽因子配置 → 归一化 → `SVC-D13` 存会话级配置，提示模型继续调 TOOL-C02 |
| TOOL-C02 | `run_backtest()` | C → GLM | LLM 工具：读 `SVC-D12` 当前配置 → `SVC-D19` 回测 → 产出 report 卡；无配置则提示先选因子 |
| SVC-Z01 | `ZhipuService.configured` / `defaultModel` | zhipu → B | Key 是否配置、当前模型名（API-01 的数据源） |
| SVC-Z02 | `ZhipuService.chat(messages, options)` | zhipu（备用） | 智谱直连 chat（**主链路不经此**，agent 用 LangChain ChatOpenAI 直连） |
| SVC-Z03 | `ZhipuService.chatStream(messages, options)` | zhipu（预留） | 流式直连，为 SSE 流式回复预留 |
| SVC-D01 | `StoreService.listStrategies()` | D → B | 策略列表 |
| SVC-D02 | `StoreService.getStrategy(id)` | D → B | 单个策略 |
| SVC-D03 | `StoreService.saveStrategy(strategy)` | D → B | 保存/更新策略 |
| SVC-D04 | `StoreService.deleteStrategy(id)` | D → B | 删除策略 |
| SVC-D05 | `StoreService.listConversations()` | D → B | 会话列表（倒序） |
| SVC-D06 | `StoreService.getConversation(id)` | D → B | 单个会话 |
| SVC-D07 | `StoreService.newConversation()` | D → B | 新建会话（带欢迎语） |
| SVC-D08 | `StoreService.deleteConversation(id)` | D → B | 删除会话 |
| SVC-D09 | `StoreService.clearConversation(id)` | D → B | 清空会话（恢复欢迎语、重置标题） |
| SVC-D10 | `StoreService.appendMessages(id, msgs)` | D → B | 追加消息 |
| SVC-D11 | `StoreService.renameConversationFromFirstMessage(id, text)` | D → B | 按首条消息前 16 字命名会话 |
| SVC-D12 | `StoreService.getLastReport(convId)` | D → B/C | 读会话级"当前策略配置"（C 的记忆） |

| SVC-D14 | `StoreService.getFactorLib()` | D → B | 因子库 9 项（API-14 数据源） |
| SVC-D15 | `StoreService.getBtParams()` | D → B | 回测参数项（API-15 数据源） |
| SVC-D16 | `StoreService.getStockPool()` | D → B/D | 演示股票池 16 只 |
| SVC-D17 | `StoreService.getProfile()` | D → B | 用户资料（API-17 数据源） |
| SVC-D18 | `StoreService.updateSetting(key, patch)` | D → B | 更新设置项（API-18 数据源） |
| SVC-D19 | `BacktestService.runBacktest(input): BacktestOutput` | D → B/C | 回测：入参 `{seedKey, factors, universe, rebalance}`；契约口径：曲线起点 100、百分比 `14.6`、确定性可复现 |
| SVC-D20 | `ScreenService.screen({universe?, filters[], topN?}): ScreenResult` | D → B/C | 选股筛选（字段/操作符白名单，非法 → 400） |
| SVC-D21 | 共享常量与工具导出 | D → B/C | `normalizeWeights`（权重归一化）、`toMetricItems`、`mkBench`、`todayStr`、`nowTime`、`WELCOME_TEXT`、`BT_DEFAULTS`、`CURVE_*`、`STOCK_POOL`、`LastReport`/`StockMeta` 类型 |

模块内部接口：C-INT-01 `loadFactorKnowledge(): string`（读 `docs/factors.md` 注入提示词，
mtime 缓存，改文档即生效）。

### 3.4 外部接口（EXT-01）

| 编号 | 接口 | 消费方 | 说明 |
|---|---|---|---|
| EXT-01 | 智谱 GLM（OpenAI 兼容协议，chat/completions 含 tool-calling） | C（主链路 LangChain ChatOpenAI；zhipu 备用直连） | `.env` 配置：`ZHIPU_API_KEY`、`ZHIPU_MODEL`、`ZHIPU_BASE_URL`、`CHAT_TIMEOUT_MS`。未配 Key → C 走规则+模板兜底；调用失败 → 回复仅含失败原因、不带卡片、不静默降级 |

## 4. 模块总表：需要什么接口 / 提供什么接口

| 模块 | 需要的接口 | 提供的接口 |
|---|---|---|
| **A 前端**（factor-agent-react） | API-01 ~ API-18（全部 18 个） | 面向用户的 Web UI（产品形态，无编号接口） |
| **B 后端业务层**（conversations/strategies/market/user + common + main） | 跨模块：SVC-C01、SVC-D01~D21、SVC-Z01；模块内：B-INT-01~04（controller → service） | API-01 ~ API-18 |
| **C 智能体引擎**（agent + zhipu + docs/factors.md） | SVC-D12、SVC-D13、SVC-D19、SVC-D20、SVC-D21（部分）；EXT-01；C-INT-01（内部） | SVC-C01；TOOL-C01、TOOL-C02；SVC-Z01~Z03（zhipu 提供，当前仅 B 的 API-01 用到） |
| **D 核心领域层**（core，最底层） | 无（只依赖 NestJS 框架） | SVC-D01 ~ SVC-D21 |

**关键职责线**：B 是 D 的唯一写入口（会话/策略/用户主数据的增删改都经 B）；
C 只读写 `SVC-D12/D13` 会话级配置缓存，不碰主数据；所有跨模块调用只依赖接口（abstract），
实现可整体替换而不影响上层。

## 6. 协作约定

**目录所有权**：只改自己模块的目录。共同文件与对齐点：

| 文件 | 归属 | 另一方注意 |
|---|---|---|
| `factor-agent-react/docs/backend-api.md` | 契约文档 | API-xx 字段变更先改契约，再改实现 |
| `src/types.ts`（A、B 各一份） | A/B 共同维护 | 字段必须一致，双侧同步 |
| `factor-agent-server/docs/factors.md` | C | 改因子定义不用改代码，但 B 需同步 API-14 下发内容 |

**接口变更流程**：改接口 = 改契约文档编号条目 → 改接口文件 → 改实现 → 跑通
`factor-agent-server/docs/technical.md` §10 验证清单。编号（API-xx/SVC-xx/B-INT-xx）保持稳定，
新增追加编号，废弃保留编号并标注。

**新增实现**：在对应 `implementations/` 下加文件 + module 改一行 `useClass`，
接口与上层代码零改动。

**联调方式**：后端 `npm run start:dev`（3000）+ 前端 `npm run dev`（5173，Vite 代理 /api）；
前端在后端不可达时自动走 mock 兜底。

**建议开发顺序（按模块认领）**：

| 优先级 | 任务 | 归属模块 | 说明 |
|---|---|---|---|
| P0 | 流式回复（SSE，走 SVC-Z03 预留 + API-07 改造） | B + C + A | 契约 §5 已定义报文 |
| P0 | 数据库存储实现（implementations/ 下新增） | D | module 切 useClass，B/C 零改动 |
| P1 | 真实行情回测/筛选实现 | D | 对接 Tushare/聚宽等；数据接入收敛在 D，A/B/C 无感 |
| P1 | 登录鉴权 + 多用户数据隔离 | B | `Authorization: Bearer` 已预留，涉及 API-01~18 |
| P2 | 回测进度查询 / 报告导出 PDF | B + D | 契约 §5 可选项 |
| P2 | Capacitor 打包 APP | A | 前端代码零改动，纯工程配置 |
