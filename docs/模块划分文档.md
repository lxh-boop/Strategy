# 因子智投（AlphaSage）模块划分与协作文档

> 面向多人协作的模块划分说明：项目分为哪几部分、每部分的功能职责、对内对外接口。
> 接口细节的**权威契约**是 `factor-agent-react/docs/backend-api.md`，本文档与其保持同步；
> 两者冲突时以代码实际实现为准，并回改文档。

---

## 1. 项目总览

**产品**：多因子选股智能体。用户通过对话让智能体构建因子策略、执行回测、筛选股票；
"我的策略"页管理策略与回测报告；"个人中心"管理偏好、设置与 API 密钥。

**技术栈**

| 端 | 技术 | 端口 |
|---|---|---|
| 前端 | React 18 + TypeScript + Vite（纯 SVG 图表，无图表库） | 5173（开发，/api 代理到 3000） |
| 后端 | NestJS 11 + TypeScript | 3000 |
| 智能体 | LangChain + LangGraph（JS 版）tool-calling | — |
| 大模型 | 智谱 GLM（OpenAI 兼容协议，`@langchain/openai` ChatOpenAI 接入） | — |

**仓库结构（本仓库为 monorepo）**

```
Agent/
├── docs/                      # 仓库级文档（本文档）
├── factor-agent-react/        # 【模块 A】Web 前端
├── factor-agent-server/       # 【模块 B/C/D】NestJS 后端（B 业务接口 / C 智能体 / D 核心领域）
└── factor-agent-ui/           # 旧版 HTML/JS 原型，仅作参照，不再开发（可归档）
```

**架构与数据流**

```
浏览器
  │  REST (JSON, /api/*)
  ▼
【A】factor-agent-react ──Vite 代理──▶ 【B】后端业务接口层（NestJS Controllers）
                                          │
                        ┌─────────────────┼──────────────────┐
                        ▼                 ▼                  ▼
                  【C】智能体引擎      【D】核心领域层
                  agent.service        store.service      （内存存储 + 种子数据）
                  (LangGraph 图)       backtest.service   （模拟回测引擎）
                        │              screen.service     （选股筛选）
                        ▼
                  智谱 GLM（OpenAI 兼容协议）
                  因子知识库 docs/factors.md（提示词唯一数据源）
```

## 2. 模块划分总表

| 模块 | 名称 | 代码目录 | 建议人数 | 一句话职责 |
|---|---|---|---|---|
| **A** | Web 前端 | `factor-agent-react/` | 1~2 | 三个页面 + 公共组件 + API 封装，全部数据来自后端 |
| **B** | 后端业务接口层 | `factor-agent-server/src/{conversations,strategies,market,user}` + `common` + `main.ts` | 1 | 实现 18 个 REST 接口，参数校验、错误格式、编排 C/D |
| **C** | 智能体引擎 | `factor-agent-server/src/{agent,zhipu}` + `docs/factors.md` | 1~2 | LangGraph 工具循环、GLM 接入、提示词与因子知识库 |
| **D** | 核心领域层 | `factor-agent-server/src/core` | 1 | 存储与种子数据、回测引擎、选股筛选（未来接真实数据） |

> 3 人团队建议：A 一人，B+D 一人，C 一人。D 当前代码量小，可与 B 合并；
> 若接真实行情/数据库，D 工作量会显著上升，建议独立。

**当前边界（所有人都要知道）**：存储是**内存态**（重启恢复种子数据）；回测是**模拟引擎**
（种子伪随机、确定性，同一配置永远同一份报告）；未接登录与鉴权（`Authorization: Bearer` 预留）。

## 3. 各模块功能与接口

### 模块 A：Web 前端（factor-agent-react）

**功能职责**

1. **对话选股（ChatPage）**：多会话管理（新建/切换/删除/清空，数据存后端）、多轮上下文；
   渲染智能体返回的三种结构化卡片（report 策略构建 / backtest 回测 / stocks 选股），
   report 卡可一键保存为策略；
2. **我的策略（StrategiesPage）**：统计总览、策略卡片（收益曲线/指标）、详情弹窗
   （因子权重滑杆、当前持仓、回测参数）、新建策略；保存权重 = 后端自动归一化并重新回测；
3. **个人中心（ProfilePage）**：用户信息、因子偏好雷达图、偏好设置（开关/风险偏好）；
   模型（智谱 GLM）与数据来源为**只读展示**，由平台统一提供，不支持用户配置；
4. **公共设施**：纯 SVG 图表组件（净值曲线/区间收益条/雷达图）、Modal/Toast、
   统一 API 封装与错误处理。

**代码目录**

```
factor-agent-react/src/
├── api.ts                  # 全部后端请求封装（fetch + ApiError）★接口变更只改这里
├── config.tsx              # 配置型数据 Context（因子库/回测参数由后端下发）
├── types.ts                # 全局类型（必须与后端 src/types.ts 保持一致）
├── hooks/useConversations.ts   # 多会话状态（乐观更新/回滚）
├── components/{charts,ui,icons}.tsx
├── data/mock.ts            # 快捷指令文案 + 后端不可达时的兜底数据
├── utils/format.ts
└── pages/{ChatPage,StrategiesPage,ProfilePage}.tsx
```

**依赖的接口**：§4.1 全部 18 个 REST 接口。

**协作注意**：页面之间互不依赖，可按 ChatPage / StrategiesPage+ProfilePage 拆给两人；
`types.ts` 与 `api.ts` 是前后端对齐点，改动需同步模块 B。

### 模块 B：后端业务接口层（NestJS Controllers）

**功能职责**

1. 实现 §4.1 的 18 个 REST 接口（路由、参数校验、统一错误格式）；
2. 会话模块：编排"调智能体 → 存消息 → 自动命名会话标题"；
3. 策略模块：权重归一化兜底、"保存配置 = 自动重新回测"语义；
4. 市场数据模块：因子库 / 回测参数下发（UI 数据驱动）、选股筛选入口；
5. 用户模块：个人资料、设置项（notify/report/risk 可配置；模型与数据来源为 readonly 展示）。

**代码目录**

```
factor-agent-server/src/
├── main.ts                     # 入口：CORS、全局校验管道、统一错误过滤器
├── app.controller.ts           # GET /api/health
├── types.ts                    # 与前端 types.ts 一致的共享类型
├── common/                     # ApiException + 全局异常过滤器（错误格式唯一出口）
├── conversations/              # 会话：controller / service / module / dto
├── strategies/                 # 策略：controller / service / module / dto
├── market/                     # 因子库 / 回测参数 / 选股筛选
└── user/                       # 个人中心
```

**提供的接口**：§4.1 全部（按模块分组的 18 个）。

**调用的内部接口**：C 的 `AgentService.reply()`、D 的 `StoreService` / `BacktestService` / `ScreenService`。

---

### 模块 C：智能体引擎（LangGraph + 智谱 GLM）

**功能职责**

1. **LangGraph 工具循环**：`START → agent(GLM，绑定 2 个工具) ⇄ tools → 最终文案`；
   两个工具由 GLM 自主决定调用时序与参数：
   - `select_factors`：抽取因子/权重/股票池/调仓/命名，记录会话级策略配置；
   - `run_backtest`：对当前配置执行回测，产出报告卡片；
2. **多轮语义**："再回测一下它"复用会话级配置重跑；"把低波动提到 40"= 基于当前配置
   修改后重新选因子 + 回测；构建策略 = 先 `select_factors` 再 `run_backtest`；
3. **非工具分支**：筛选/ROE/估值类消息走规则分支产出 stocks 卡片（演示功能）；
   问候/闲聊纯文本回复，不生成卡片；
4. **因子知识库**：`factor-agent-server/docs/factors.md` 是 LLM 因子来源的**唯一数据源**
   （9 个因子的定义/指标/权重区间/风格搭配 + 传参规则），组装提示词时全文注入
   （按文件修改时间缓存，编辑保存后下一次请求即生效）；
5. **降级与错误语义**：未配 Key → 关键词规则 + 模板文案（开发模式）；配了 Key 但调用失败
   （429/403/超时）→ 回复仅含失败原因，**不附带卡片、不静默降级**；LLM 不接触数值生成，
   卡片数据全部来自 D 的回测引擎，不会编造数据。

**代码目录**

```
factor-agent-server/src/
├── agent/agent.service.ts      # LangGraph 状态图 + 2 个工具 + 文案生成
├── agent/factor-knowledge.ts   # factors.md 加载与缓存
├── zhipu/                      # 智谱直连客户端（health 探测与备用，主链路走 LangChain）
└── docs/factors.md             # 因子知识库（本模块的"数据文件"）
```

**对内提供的接口**（模块 B 调用）

```ts
// agent.service.ts
reply(conversation: Conversation, userText: string, routeText: string): Promise<AgentReply>
// AgentReply = { bubble: string; card?: AgentCard }（card 三种：report / backtest / stocks）
```

**依赖**：D 的 `BacktestService`（工具执行时产出卡片数据）、`StoreService`（会话级配置存取）；
外部：智谱 GLM（OpenAI 兼容协议，`.env` 配 Key/模型/端点）。

---

### 模块 D：核心领域层（数据与算法）

**功能职责**

1. **存储（store.service）**：内存存储 + 种子数据（4 个策略、示例用户、9 因子库、股票池），
   接口形态已定型，后续平滑换数据库；
2. **回测引擎（backtest.service）**：模拟回测，种子伪随机保证确定性
   （回测种子 = 会话+配置），产出净值曲线/指标/持仓；
3. **选股筛选（screen.service）**：按 `{universe, filters, topN}` 过滤股票池。

**代码目录**

```
factor-agent-server/src/core/     # 全局模块（GlobalModule，各业务模块直接注入）
├── store.service.ts
├── backtest.service.ts
└── screen.service.ts
```

**对内提供的接口**（模块 B/C 调用）

```ts
// store.service.ts —— 策略
listStrategies(): Strategy[]            getStrategy(id): Strategy | undefined
saveStrategy(s: Strategy): void         deleteStrategy(id): boolean
// 会话
listConversations(): Conversation[]     getConversation(id): Conversation | undefined

clearConversation(id): Conversation | undefined
appendMessages(id, msgs: ChatMessage[]): Conversation | undefined
renameConversationFromFirstMessage(id, text): void
// 会话级智能体配置缓存
getLastReport(convId): LastReport | undefined    setLastReport(convId, report): void
// 配置型数据
getFactorLib(): FactorLibItem[]         getBtParams(): BtParamItem[]    getStockPool(): StockMeta[]
// 用户

// 算法
// backtest.service.ts

// screen.service.ts

```

**后续演进（这一模块的主线工作）**：接真实行情数据源 → 替换 backtest/screen 实现；
换持久化 → 替换 store 实现。接口签名不变，B/C 无需改动。

## 4. 接口文档

### 4.1 前端 ↔ 后端 REST API（模块 A ↔ B，共 18 个）

通用约定：Base URL `/api`；JSON；错误统一 `{ "error": { "code": "...", "message": "..." } }`
+ HTTP 状态码；鉴权预留 `Authorization: Bearer <token>`。
**数值口径（重要）**：百分比是 `14.6`（14.6%）不是 0.146；净值曲线起点固定 100；
因子权重归一化为合计 100（1 位小数，残差补给最大项，合计 0 → 400）；
策略 `updatedAt` 为 `YYYY-MM-DD`，消息 `time` 为 `HH:mm`，会话 `updatedAt` 为毫秒时间戳。

**健康检查**

| 方法 | 路径 | 说明 |
|---|---|---|
| GET | `/api/health` | 健康检查，返回含 `zhipuConfigured`（Key 是否已配置） |

**会话模块**（B 的 conversations/ ↔ A 的 ChatPage）

| 方法 | 路径 | 说明 |
|---|---|---|
| GET | `/api/conversations` | 会话列表 |
| POST | `/api/conversations` | 新建会话（带欢迎语） |
| DELETE | `/api/conversations/:id` | 删除会话 |
| POST | `/api/conversations/:id/clear` | 清空会话消息 |
| GET | `/api/conversations/:id/messages` | 拉取历史消息 |
| POST | `/api/conversations/:id/messages` | **发消息**，同步返回 `{userMessage, agentMessage}`（agent 消息可含卡片） |

发消息请求 `{ "text": "帮我构建一个小盘动量策略" }`；响应中 `card` 为三种卡片之一
（report / backtest / stocks，结构见 §4.2 末尾与契约 §2.2）。
会话标题 = 首条用户消息前 16 字自动命名。

**策略模块**（B 的 strategies/ ↔ A 的 StrategiesPage）

| 方法 | 路径 | 说明 |
|---|---|---|
| GET | `/api/strategies` | 策略列表（含曲线与持仓） |
| POST | `/api/strategies` | 创建策略（草稿，metrics 为 null） |
| PATCH | `/api/strategies/:id` | 更新配置 = **自动重新回测**，直接返回更新后的完整 Strategy |
| POST | `/api/strategies/:id/backtest` | 重新回测（可带 period/topK/feeRate） |
| GET | `/api/strategies/:id/report` | 回测报告详情 |
| DELETE | `/api/strategies/:id` | 删除策略 |

PATCH 传入权重**不要求合计 100**，后端按比例归一化（前端已实现同一算法 `normalizeWeights`，
后端兜底执行，合计 0 → 400）。

**市场数据模块**（B 的 market/ ↔ A 的 config.tsx / ChatPage）

| 方法 | 路径 | 说明 |
|---|---|---|
| GET | `/api/factors` | 因子库（9 个：`{id, name, desc}`），UI 数据驱动 |
| GET | `/api/backtest-params` | 回测参数项（后端下发，UI 自动渲染） |
| POST | `/api/screen` | 选股筛选 `{universe, filters:[{field,op,value}], topN}` → `{stocks, total}` |

**用户模块**（B 的 user/ ↔ A 的 ProfilePage）

| 方法 | 路径 | 说明 |
|---|---|---|
| GET | `/api/user/profile` | 用户信息 + 因子偏好雷达 + 设置项（模型/数据来源为 readonly 展示） |
| PATCH | `/api/user/settings` | 更新设置项，仅 notify/report/risk 可配置：toggle 传 `on`、single 传 `value`；其余 key 返回 400 |

> 产品边界（2026-09-28）：大模型统一智谱 GLM、行情数据统一使用平台内部数据，均由服务端
> 配置，不提供用户级模型/数据源配置；`model` 与 `datasource` 为 readonly 展示项。

> 完整请求/响应示例见 `factor-agent-react/docs/backend-api.md` §3；
> 接口明细与发消息完整时序见 `factor-agent-server/docs/technical.md` §6。

### 4.2 业务层 ↔ 智能体引擎（模块 B ↔ C，进程内调用）

```ts
// conversations.service.ts 调用：
AgentService.reply(conversation: Conversation, userText: string, routeText: string)
  → Promise<{ bubble: string; card?: AgentCard }>
```

`AgentCard` 三种（完整字段见契约 §2.2）：

```ts
{ type: "report",   title, tag, factors, curve, benchCurve, benchName, metrics, rawMetrics, universe, rebalance, note }
{ type: "backtest", title, tag, curve, benchCurve, benchName, metrics, note }
{ type: "stocks",   title, tag, stocks: [{code, name, score, weight}], note }
```

约定：C 只产出**文案 + 卡片**，不直接写存储（由 B 落库）；卡片数值全部来自 D 的引擎；
`factors.md` 是 C 的提示词数据源，**改因子定义只需改该文件，无需改代码**。

### 4.3 业务层/智能体 ↔ 核心领域层（模块 B/C ↔ D，进程内调用）

方法签名见 §3 模块 D。调用约定：

- B 是 D 的**唯一写入口**（会话/策略/用户数据的增删改都经 B 的 service）；
  C 通过 `getLastReport/setLastReport` 读写会话级策略配置，其余只读；
- `runBacktest` 输入输出为纯数据（`BacktestInput/BacktestOutput`），无副作用；
- D 替换实现（真行情/真数据库）时**不得改变方法签名**，B/C 代码零改动。

### 4.4 智能体 ↔ 智谱 GLM（模块 C ↔ 外部）

OpenAI 兼容协议（`@langchain/openai` ChatOpenAI）。`.env` 配置：
`ZHIPU_API_KEY`（不填走模板兜底）、`ZHIPU_MODEL`（默认 glm-4-flash；套餐模型如
glm-5.3-flash 必须把 `ZHIPU_BASE_URL` 改为 `…/api/coding/paas/v4`）、`CHAT_TIMEOUT_MS`（默认 20000）。

## 5. 协作约定

**目录所有权**：改代码只改自己模块的目录；跨模块改动（如 `types.ts`、接口字段）
在群里/提交说明中同步对方模块的负责人。共同文件：

| 文件 | 所属 | 另一方注意 |
|---|---|---|
| `*/src/types.ts`（前后端各一份） | A/B 共同维护 | 字段必须一致，改动双侧同步 |
| `factor-agent-react/docs/backend-api.md` | 契约文档 | 接口变更先改契约，再改实现 |
| `factor-agent-server/docs/factors.md` | C | 改因子定义不用改代码，B 需同步 `/api/factors` 下发内容 |

**分支建议**：`main` 保持可运行；开发走 `feat/<模块>-<内容>` 分支
（如 `feat/agent-stream`、`feat/ui-strategy-detail`），自测通过后合入；
接口类改动合入前跑一遍 `factor-agent-server/docs/technical.md` §10 的验证清单。

**联调方式**：后端 `npm run start:dev`（3000）+ 前端 `npm run dev`（5173，Vite 已代理 /api）；
前端不启动后端时自动走 mock 兜底，可离线开发页面。

**建议开发顺序（按模块认领）**

| 优先级 | 任务 | 归属模块 | 说明 |
|---|---|---|---|
| P0 | 流式回复（SSE）：先推 text delta 再推 card | B + C + A | 契约 §5 已定义报文，改动集中在发消息链路 |
| P0 | 持久化：内存存储 → SQLite/MySQL | D | 方法签名不变，B/C 零改动 |
| P1 | 接真实行情数据源，替换模拟回测 | D | 对接 Tushare/聚宽等外部供应商；数据接入收敛在模块 D，A/B/C 无感 |
| P1 | 登录鉴权 + 多用户数据隔离 | B | `Authorization: Bearer` 已预留，涉及全部接口 |
| P2 | 回测进度查询 / 报告导出 PDF | B + D | 契约 §5 可选项 |
| P2 | Capacitor 打包 APP | A | 前端代码零改动，纯工程配置 |
