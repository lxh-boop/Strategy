# 回测卡片会话级编号与独立存储方案

日期：2026-10-23 ｜ 状态：grill 定案，实施未开工（等开工令） ｜ 关联：ADR-0010、GLOSSARY「回测卡编号」

## 1. 背景与事故复盘

2026-10-23 调优轮（会话 c1792718195836sp58 13:17）：模型先跑 `run_factor_correlation`（相关性分析）再跑 4 组回测。卡片编号是**回合内临时号**（tools 节点对任何产卡工具顺序发号，thread 每轮新建即重置，langgraph-agent.service.ts:341/368），相关性分析卡占了 card_1，四组回测实际为 card_2~card_5。模型按"第 N 组方案 = card_N"心算，最终标记【展示卡片：card_4】实际选中第 3 组 rank20（+23.8%），而文本声称的最优方案④ IC 加权（+39.8%，card_5）从未展示——落库消息固化了错误卡片。

深层问题：①编号是回合临时指针，不是会话事实；②多组回测只有被选中的一张落库，其余随轮次蒸发（用户产品基线："回测无偏，实盘亏损应归于策略而非回测失真"——调优证据链不可回看）。

## 3. 功能清单

- **F1 会话级持久编号**：card_N = 本会话第 N 次回测，seq 永不重置、跨轮稳定；回执「卡片编号」即会话级编号，模型原样引用（prompt 禁止按组序推算）。
- **F2 回测完成即入册**：回测工具成功即写 runs 表（先于模型择优），**未被展示的组同样保存**；相关性/排名分析卡不占号不入册。
- **F3 展示语义**：一轮仍只展示一张卡（card 通道 last-write）；模型择优后调 get_backtest_run 把最优组调出展示；落库消息 card 列照旧存展示卡对象。
- **F4 跨轮回看**：get_backtest_run 按 (conversation_id, seq) 查 runs——命中即把历史卡调出展示（含上一轮/更早的组），展示副本随当轮消息落库。
- **F5 删除级联**：删除会话 → 级联删除该会话全部 runs；单条消息与 runs 无绑定（删消息不动 runs）。
- **F6 存量迁移**：一次性迁移历史 backtest 卡入 runs，按会话按消息顺序补 seq；其余类型不迁。
- **F7 回测存档查询与调取工具**（2026-10-23 三次修正定稿：用户拍板 system 能精简尽量精简、**否决规则匹配标记机制**——展示改由工具完成）：`list_backtest_runs`（返回本会话 runs 索引：卡片编号/日期/标题）+ `get_backtest_run`（按编号调取，**完整卡片经 tool 产物通道直达前端**，摘要给模型）；**GLM 依旧只见摘要，只信卡片原则不变**。【展示卡片：card_N】文本标记机制废除。
- **明确不做**：见 Q6。

## 4. 存储与实现设计

### 新表 backtest_runs（alphasage_user 库）

```sql
CREATE TABLE backtest_runs (
  id BIGINT AUTO_INCREMENT PRIMARY KEY,
  conversation_id VARCHAR(64) NOT NULL,
  username VARCHAR(64) NOT NULL,
  seq INT NOT NULL,
  title VARCHAR(200) NOT NULL,
  card JSON NOT NULL,
  created_at DATETIME DEFAULT CURRENT_TIMESTAMP,
  UNIQUE KEY uq_conv_seq (conversation_id, seq),
  KEY idx_user (username)
);
```

card 列存完整卡片对象（曲线/交易/每期持仓/config/params 全在里头）；title 供将来回测历史列表展示。seq 分配依赖同会话消息级并发闸（inflightRuns 单飞），`MAX(seq)+1` 无竞态。

## 5. 验收标准

1. 授权调优轮 N 组全部入册（seq 连续、按完成序），落库展示卡与文本声称的最优组**一致**（本轮事故回归）；
2. 分析卡（相关性/排名分析）不产生编号、不进 runs；
3. 跨轮回看：新轮次用历史 card_N 引用，展示与落库正确；
4. 删会话后 runs 表该会话行清零；
5. 迁移后：历史 backtest 卡在 runs 可查、seq 连续、类型非 backtest 的卡不迁；
6. 全量测试绿 + 授权调优真图冒烟一轮。

## 6. 边界与已知取舍

- **双写冗余**：展示卡在 runs 与消息列各一份（30KB 级）——接受；将来嫌大升级为消息列存引用（方案 Q3-A）。
- **runs 无上限**：会话存活期间永久保留，随会话删除清理——不做数量限制。
- **跨轮引用乱指**：模型可能引用非用户意图的旧卡——索引注入保证它"看得见目录"，prompt 场景约束（仅用户要求回看时引用）+ 展示副本可追溯，风险可控。
- **模型对历史组的认知边界**：只有 list_backtest_runs 的索引级信息（编号/日期/标题）；更深的明细（月度收益等）仅存在于其所在轮次的对话文本里——v1 不加"查询单次回测明细"工具，需要时再挂。
- **上轮事故善后**：该调优轮丢失的 4 组结果不可恢复（仅摘要数字在文本里）；实施后重跑一次调优即可重建完整档案。
