# 权重与仓位函数化改造方案（函数注册表 · 策略旋钮）

> 版本 v1（2026-10-17）· 状态:**已评审定案，待实施**
> 依据:ADR-0005《权重与仓位函数化：GLM 传函数名，注册表求值》、GLOSSARY.md「权重函数」词条簇、grill 三轮定案（2026-10-17）。
> 前置确认（grill 已拍板）:① GLM 传**函数名+参数**（字符串），解析在后端注册表；② 因子值唯一事实 = 数据库，先缓存后取数，**不存在计算因子的地方**；③ 仓位函数返回**金额字典**（每股金额，甚至直接是买入金额）；④ 现有功能**内化成函数**（1/N 等权、静态权重列都是 `constant` 的参数形态）；⑤ 函数需要参数（schema 化），GLM 只用函数名调用；⑥ 初始目录只内置 `constant` 一个；⑦ 校验独立成模块（整手/现金/上限，逐条修正不硬拦）；⑧ 缺值沿用现状静默处理；⑨ 注册表代码内置（方案 a）。

---

## 1. 背景与目标

### 1.1 现状

- **因子权重**:`sortFactors[].weight`（可选，缺省 1/N 等权），`rankUniverse`（strategy-backtest.service.ts:783）加权综合分——静态数字，回测全程不变
- **持仓仓位**:等权（统一目标仓位百分比）+ 保护参数 `idealPositionPct`/`minPositionPct`/`positionDeviatePct`
- 分层纪律:v3 设计原则"GLM 只做语义→数字，**引擎只收数字参数**"（大盘择时方案 §2）——本方案正式修订为"引擎收数字参数**或注册表函数引用**"（ADR-0005）
- 《大盘择时重构方案》§1.2"模型 Ⅲ 定期轮动+公式权重"（果仁"股票仓位权重由公式决定"）标待实现——本方案交付其函数化部分

### 1.2 目标

1. 统一函数字典:一张（代码内置），权重/仓位函数都登记其中（`kind` 字段区分用途）；`weightFn`/`positionFn` 只是回测函数的两个参数，各自按 `{name, params}` 引用字典条目——参数本身有自己的参数
2. `constant` 函数双版:因子权重版（内化静态 weight 列）、仓位版（名次比例 × 当期剩余现金 → 金额字典）
3. 独立校验器:整手/现金/上限逐条修正 + 违规清单进回执
4. 参数简洁原则落进注册表契约:**参数只放策略旋钮，数据由引擎上下文供给**

### 1.3 改造后新增能力（之前没有的）

| # | 用户能做的事（对话示例） | 之前 | 之后 |
|---|---|---|---|
| 1 | "因子权重 REVS20 给 0.5、Volume1M 给 0.3" | 静态数字列（全程不变） | 函数参数，语义相同但走统一函数通道 |
| 2 | "第一名买 40%、第二名 30%……" | 只能等权 | 仓位函数按名次比例 × 当期剩余现金 |
| 3 | 换仓位分配规则 | 改引擎代码 | 加注册函数（发版即可，模型即点即用） |
| 4 | 因子权重按滚动 IC 自适应 / 仓位按因子值（如 BIAS20）正部定比 | 只有静态权重与等权 | ic_weight / factor_position 函数 |
| 5 | 金额超现金/不整手 | 执行层静默处理 | 校验器逐条修正 + 违规清单进回执 |
| 6 | 历史策略复现 | — | 兼容层翻译，逐位不变 |

## 2. 设计原则（定死）

1. **参数只放策略旋钮**:函数参数只承载策略选择（比例数组、衰减系数）；一切数据类输入（因子截面、IC、名次、剩余资金）由引擎上下文供给——参数越少，GLM 出错越少
2. **函数名即接口**:模型输出永远不是代码；注册表按名解析执行，确认门展示函数中文名+参数
3. **等权内化**:`constant` 无参/缺参 = 等权，现状行为是函数的特例而非独立分支
4. **因子值唯一事实**:权重函数消费的因子截面走现有取数路径（缓存→数据库），与排序共用一次取数，不新增计算因子
5. **缺值照现状**:个股缺值该因子不计分并重归一、全部缺值出局、整列缺失因子静默跳过——零行为变化
6. **内核挂载最小化**:只在两处插函数调用点，选股流水线其余部分不动

## 3. 函数注册表

### 3.1 契约（分层：引擎只收函数，查表在边界）

```ts
// ── 引擎层（strategy-backtest）：不认识函数字典，只收已解析的函数 ──
interface FactorWeightCtx {          // 权重函数的入参（每决策日由引擎构造）
  factors: { table: string; field: string }[];
  sections: Map<string, number>[];   // 各因子候选池截面（引擎已取，缓存→DB）
  icByFactor?: Record<string, number>; // 各因子滚动 Rank IC 均值（ic_weight 消费，引擎按窗口预计算）
  pool: string[];
  count: number;
}
interface PositionCtx {              // 仓位函数的入参
  candidates: { code: string; rank: number; score: number }[];  // 本期拟买入
  sizingSection?: Map<string, number>; // 定权因子截面（factor_position 的 params 因子引用，引擎预取，缓存→DB）
  remainingCash: number;
  remainingPct: number;
  maxPositions: number;
}
// StrategyBacktestInput 新增（已解析、已绑定参数的函数）：
weightFn?:   (ctx: FactorWeightCtx) => number[];                    // 各因子权重（引擎归一化）
positionFn?: (ctx: PositionCtx) => Record<string, number>;          // 股票→买入金额

// ── 编排层（core/weight-functions.ts）：唯一函数字典只在这里存在 ──
interface FnDef {                    // 字典条目：用途标记 + 元数据 + 函数体
  kind: "factor-weight" | "position";  // weightFn/positionFn 参数各引其 kind
  description: string;               // 中文说明：进工具 schema 与确认门
  paramSchema: JsonSchema;           // 旋钮参数校验（可为空 schema）
  fn(ctx: FactorWeightCtx | PositionCtx, params: unknown): number[] | Record<string, number>;
}
const FUNCTIONS: Record<string, FnDef>;   // 唯一函数字典，权重/仓位共用一张（name 全局唯一）
function resolveFn(kind, spec?: { name: string; params?: object }):
  已绑定参数的函数;   // 查字典（name 唯一）+ kind 匹配 + paramSchema 校验 + 绑定参数；缺省 = 对应 kind 的 constant
```

**调用链**:GLM 在回测函数的两个参数上各传 `{name, params}` → 编排层 `resolveFn(kind, spec)`（查同一张字典 + 校验 + 绑定，**边界上一次**）→ 绑定函数放进引擎输入 → 引擎每调仓 `weightFn(ctx)` / `positionFn(ctx)`。引擎热路径与函数签名里都没有字典概念；`FactorWeightCtx`/`PositionCtx` 就是两个函数的直接入参。

### 3.2 v1 目录:constant 两条（同一张字典，name 全局唯一）

| 字典条目 | kind | 参数 | 语义 | 缺省行为 |
|---|---|---|---|---|
| `constant_weights` | factor-weight | `{ weights: number[] }` 按因子登记顺序对位 | 各因子固定权重（引擎归一化） | weights 缺省 = 等分（1/N 等权，现状） |
| `constant_proportions` | position | `{ proportions: number[] }` 按名次对位 | 第 k 名金额 = 第 k 个比例 × 当期剩余现金 | proportions 缺省 = 等分（等权金额，现状） |
| `ic_weight` | factor-weight | `{ icWindow: number = 20 }` 滚动窗口交易日数 | 各因子滚动 Spearman Rank IC 均值正部归一化定权（负 IC 记 0） | — |
| `factor_position` | position | `{ factor: { table, field } }` 定权因子引用（如 equ_factor_obos.BIAS20） | 正部比例加权：仓位_i ∝ max(值_i,0)，全 ≤0 该期空仓并告警 | — |

GLM 视角:两个参数各引一条——`weightFn: { name: "constant_weights", params: {...} }`、`positionFn: { name: "constant_proportions", params: {...} }`；kind 不匹配（如 weightFn 引了 position 条目）→ resolve 时拒绝。

**对位宽容规则**（定案）:数组短于条目数 → 剩余条目平分剩余比例；长于 → 截断；总和 <1 → 差额留现金；总和 >1 → 按比例缩放到 1（后续仍过校验器）。

**约束的由来**:GLM 生成参数时不知道运行期的股票代码与现金——参数只能是份额比例，金额必然是函数在每期用当期剩余现金的换算输出。

### 3.3 扩充原则

新函数（`inverse_std`、`rank_linear` 等）= 函数字典加条目（声明 kind）+ 按需扩引擎上下文字段；GLM 参数保持 0~2 个旋钮（`inverse_std` 的 params 甚至可以为空——std 由引擎算好放进 ctx）。

### 3.4 信号函数的数据管线与决策日语义（ic_weight / factor_position）

- **ic_weight 数据管线**:决策日 D 上取窗口内 `icWindow` 个日频配对——(因子截面@d, d→d+1 前复权收益) 的 Spearman 秩相关均值，末对 = (D-1 截面, D 收盘收益)，T+1 开盘执行无未来泄漏；窗口内每日因子截面 + 日收益一次预取、全程复用（缓存→数据库，因子值唯一事实不变）
- **factor_position 数据管线**:参数即因子引用（如 equ_factor_obos.BIAS20 表达"站上 MA20"），引擎按字典白名单走 readFactorSection 预取截面（缓存→DB），ctx 供 `sizingSection`；正部比例加权 `仓位_i ∝ max(值_i,0)` 归一化到剩余资金，全 ≤0 → 该期空仓并告警
- **决策日语义**:调仓模式决策日 = 调仓日（预知）；触发模式决策日 = 触发日（运行时确定，模型 Ⅱ 引擎本来就逐日取截面，函数惰性求值天然兼容，挂载列第二批）；信号每日变化 ≠ 每日交易
- **与大盘择时的分工**:"指数 MA20 上方满仓、下方空仓"的**总仓位**语义归择时（果仁仓位公式即此语义——调仓前日计算、0~1 映射 0%~100%、<0 归 0 >1 封顶；我们由 timingOverlay 字段条件承载，MA 衍生字段入库即可）；factor_position 只做**个股级**加权

## 4. 参数接口与编排层

`run_strategy_backtest` schema 新增:

```
weightFn?:   { name: string; params?: object }   // 缺省 = constant 等权（现状）
positionFn?: { name: string; params?: object }   // 缺省 = constant 等权（现状）
```

- 注册表校验:name 不存在 → 报错回执（附可用名录）；params 不合 paramSchema → `ClarificationSignal` 引导模型修正（与缺参语义一致）
- `sortFactors[].weight` 从 schema **移除**；兼容层见 §7
- 确认门（formatConfirmText）追加两行:「权重函数：常数比例 [0.5, 0.3, 0.2]」「仓位函数：常数比例 [0.4, 0.3, 0.2, 0.1]」；卡片 params 透传

## 5. 引擎挂载（两处）

1. **因子权重**:每次调仓、`rankUniverse` 打分前——构造 `FactorWeightCtx` 调 `input.weightFn(ctx)` 得 `weights[]`，喂进现有加权综合分逻辑；缺值语义不动（个股缺值该因子不计分重归一、全缺出局、整列缺失静默跳过）
2. **仓位金额**:每次调仓、选股完成后——构造 `PositionCtx` 调 `input.positionFn(ctx)` 得金额字典 → **校验器** → 现有执行层（T+1/整手/费用照旧）
3. 求值时机 = 每次调仓；解析出的函数为纯函数（无 IO、无状态），同一 params 全期确定性复现；查表/校验/绑定已在编排层边界完成，引擎热路径无注册表概念

## 6. 独立校验器（core/validator 或并入 weight-functions 模块）

输入:金额字典 + 账户现金快照。检查与修正（逐条，不硬拦）:

| 检查 | 修正 | 回执 |
|---|---|---|
| 整手 | 金额向下取整到 100 股倍数 | "600519 金额修正至整手（-182 元）" |
| 现金不足 | 从后往前剔除/缩减条目 | "剔除 002743（现金不足）" |
| 仓位上限 | 超限部分削减 | "单只仓位上限触发" |

修正后金额 + 违规清单进工具回执与 params。

## 7. 兼容层（旧 config 复现）

- 载入策略 config 时:`sortFactors[].weight` 存在 → 翻译为 `weightFn = { name: "constant", params: { weights: [...] } }`（等价性由单测对拍保证）
- 等权路径:无任何权重/仓位字段 → 缺省 `constant` 等分 = 现状行为
- 旧策略保存的 config 不改写，翻译发生在装载时

## 8. 前端改造（`factor-agent-react`）

**无新增组件**:确认门与卡片 params 是通用渲染（ParamsBlock/确认参数行），函数行作为普通参数自然展示。schema 变更（weight 字段移除）不影响前端——前端不解析该字段。

## 11. 验收标准

1. 内化等价性:constant 因子权重 [0.5,0.3,0.2] ≡ 旧静态 weight 列同配置，**逐位一致**
2. 缺省回归:不传函数 → 等权路径与现状逐位一致（182 测试零回归）
3. 仓位换算:[0.4,0.3,0.2,0.1] × 当期剩余现金 → 金额字典 → 校验器修正后成交，违规清单进回执
4. 对位宽容:短/长/总和≠1 三种单测
5. 兼容复现:历史策略（静态 weight 列）经翻译层结果不变
6. 参数防线:非法函数名回执附名录；params 不合 schema → ClarificationSignal

## 12. 边界与待实现

- 触发模式（`rebalanceIntervalDays=0`）本期不支持仓位函数（偏离带有自己的仓位语义，硬叠会打架）；二期再议
- 因子权重函数的上下文本期只给截面与统计所需的原始列；`ic` 等带历史的统计量二期（涉及 PIT 边界，需先定义"用哪段历史"）
- 模型 Ⅱ 触发引擎的函数挂载列第二批（决策日惰性求值机制天然支持，纯挂载 +0.5 天）；触发模式与仓位函数的叠加语义（偏离带 × factor_position）届时定义
- "指数级均线总仓位"不做进仓位函数——与择时功能重叠，走 timingOverlay（MA 衍生字段入库，见《待补充功能清单》P2）
- 新函数（`inverse_std`/`rank_linear` 等）按"策略旋钮"原则随时扩充函数字典
- 函数名录的 token 成本:schema description 会加长（~百字级），提速改造的注入策略不变
