## 1. 背景与目标

### 1.1 现状

回测引擎 v3 具备日频事件循环、信号/执行分离(T 收盘→T+1 开盘)、A股 T+1/整手/费用、资金账户,交易模型等价于果仁**模型 Ⅰ(定期轮动)**。缺口:① 无总仓位调度(择时);② 无条件触发模式(建仓/加仓只在调仓日);③ 数据读取为一次性全量预取(内存随回测年限线性增长);④ 取数层仅进程内 LRU(SQL 结果 200 条/10 分钟/不落盘),无磁盘缓存。

### 1.2 果仁对标结论(逆向证据,详见《果仁择时逆向.md》)

- **择时** = 独立于选股的总仓位调度:指标条件逐日给出牛/熊意见 → **投票状态机**("同时满足 N 个条件由熊变牛,同时满足 M 个由牛变熊",双向阈值独立)→ 牛市满仓、**熊市分级仓位**(`position`,默认空仓)
- **交易模型**三类对标:

| 果仁 | 语义 | AlphaSage 现状 | 本方案 |
|---|---|---|---|
| 模型 Ⅰ 定期轮动 | 每 N 交易日调仓,时点开盘/收盘 | **已实现**(v3 内核) | 择时叠加进现有 v3 内核(挂载点见 §5.2),引擎本体不动 |
| 模型 Ⅱ 条件触发 | 不按日历;触发即交易;**仓位偏离带**(低于下限加仓至理想仓位、高于上限减仓) | 部分(卖出触发式,建仓/加仓仅调仓日) | **新建独立引擎**(N 交易日分块流水线+触发+偏离带),本期交付 |
| 模型 Ⅲ 定期轮动+公式权重 | "股票仓位权重由公式决定"(tooltip 泄露) | 选股后等权 | **待实现**(后续批次) |

两个关键澄清:① 模型 Ⅲ 的"加权"加在**持仓分配**(每只买多少),与本就已有的因子加权(**选谁**,sortFactors)是两回事;② 模型 Ⅰ/Ⅱ **引擎分立、构件共享**(§2-3):一致性由公共构件的单测与两引擎对拍保证,不靠强制同内核。

- **排名分析面板**:分段分层 + 因子 IC/IR + 排列单调性(r2_score)+ 市值分位图——排序因子的正确评估口径
- **择时数据矩阵**:估值(`mkt_idxd_eval`,2008 起)、两融(`fst_total`,2010 起)、资金流(`mkt_idx_mf_new`,2014 起)字典全覆盖,已登记 `SQL/` 白名单

### 1.3 目标(合并批次)

1. `timingOverlay`:字段条件 + 投票状态机 + 分级熊市仓位,两个引擎都能叠加
2. 模型 Ⅱ 条件触发:独立新引擎,`triggerMode`(rebalanceIntervalDays=0)+ `positionDeviatePct` 偏离带
3. 模型 Ⅱ 引擎数据层:**N 交易日分块流水线**(直查 MySQL),内存有界
4. 字段扩展机制:字典表物理导入后,估值/两融/资金流信号**零代码接入**
5. 回测卡片择时证据三件套

## 2. 设计原则(定死)

1. **分层纪律不变**:GLM 只做语义→数字;引擎只收数字参数
2. **完全遵守"不在线计算"原则**:择时/触发条件=字段条件,数据一律按 table.field 从白名单表读取;金叉死叉等衍生语义由字段化解决(§3.4),引擎不算
3. **引擎分立、构件共享**:模型 Ⅰ 沿用 v3 内核**主循环一行不改**(零回归);模型 Ⅱ 新建独立引擎;资金账户/T+1/整手费用/择时状态机/字段条件/统计三件套抽**公共构件库**,两引擎引用——通用逻辑只写一份,口径漂移由构件单测+对拍拦截
4. **内存有界流水线**(模型 Ⅱ 引擎):N 交易日分块、边读边算边释放;预取与计算重叠;模型 Ⅰ 保持 v3 一次性预取不变
5. **果仁语义优先**:投票状态机、双向阈值、分级熊市仓位、偏离带范式照抄逆向结论
6. **引擎不做参数寻优**(沿用 v3);授权调优护栏本期硬编码进编排层

## 3. 数据层:N 交易日分块流水线(模型 Ⅱ 引擎)

### 3.1 数据源与键形态

| 表 | 内容 | 用途 | 唯一键(键形态) | 状态 |
|---|---|---|---|---|
| `mkt_idxd` | 指数日线 OHLCV | 择时字段(CLOSE_INDEX/CHG_PCT/TURNOVER_VALUE) | TICKER_SYMBOL,TRADE_DATE | **已导入** |
| `mkt_idxd_eval` | 指数估值:PE/PB/ROE/换手/股息率/**涨跌家数** | 估值+宽度择时 | INDEX_ID,PE_TYPE,TRADE_DATE | 未导入(未登记,导入后再登记) |
| `mkt_idx_eval_ashare` | 全A 口径估值 | ERP 择时 | INDEX_ID,TRADE_DATE | 同上 |
| `mkt_idx_mf_new` | 大小单资金净流入/流出 | 资金流择时 | SECURITY_ID,TRADE_DATE | 同上 |
| `fst_total` | 沪深京两融总量 | 两融择时(全市场维度,不挂指数) | EXCHANGE_CD,TRADE_DATE | 同上 |
| `mkt_equd_adj` | 个股前复权日线 | 行情成交、模型 Ⅱ 触发域字段 | TICKER_SYMBOL,TRADE_DATE | **已导入** |

**键形态适配(实现要求)**:取数方法内部维护 `TABLE_KEY_COLUMNS`(table→键列)映射,当前 `mkt_idxd→TICKER_SYMBOL`;内部 ID 键表(INDEX_ID/SECURITY_ID)接入时增加映射条目 + `md_security` 的 TICKER_SYMBOL→内部 ID 解析,**调用方与签名不变**。`fst_total` 为交易所级全市场序列,择时/触发规则 v1 不支持,登记备用。物理表未导入时查询报错,文案提示"该表已登记但数据未导入"。

字段条件规则(择时与触发共用)与 `entryFilters`/`sellRules` 完全同构:

```ts
interface FieldConditionRule {
  table: string;                 // 白名单日期表
  field: string;                 // 白名单字段
  op: '>' | '<' | 'bw';          // 大于/小于/介于;白名单常量 TIMING_OPS,后续可追加 'xup'/'xdn'(上穿/下穿)
  value?: number; low?: number; high?: number;
}
// 条件在 D 日成立 → 投"牛"票 / 触发成立;不成立 → 投"熊"票 / 不触发(逐日重估;缺值弃权不计分母)
```

### 3.2 N 交易日分块流水线(模型 Ⅱ 引擎的预取架构,直查 MySQL)

时间轴按回测区间切成连续**块,每块 N 个交易日**(`CHUNK_DAYS`,默认 21,可配)——块边界与交易日历对齐,区间查询的起止即真实交易日,取数最干净。三阶段在相邻块重叠:

```
预取(块 k+1)── MySQL 区间查询(BETWEEN 块首/块尾交易日,按 400 只/批分片)──► 预取缓冲(深度 1~2 块)
计算(块 k)  ── 主循环:执行→结算→信号(择时投票/触发评估)──► 净值/持仓/指令/信号标记
释放(块 k-1)── 已结算块的行情行/截面整体置 null,只留聚合态 ──► 内存有界
```

- **并行 = IO 与计算重叠**:预取为 async 生产者,主循环为消费者;瓶颈在 MySQL 传输不在 CPU,v1 不做 worker 多线程,主循环只依赖"下一块就绪的 Promise",日后升级 `worker_threads` 不换骨架
- **读法**:每块一次区间查询(`TRADE_DATE BETWEEN 块首 AND 块尾`),替代逐日查询;字段序列按 rules/sellRules 引用的 table.field 聚合预取
- **释放纪律**:块对象在主循环越过该块最后一个交易日后整体置 null;长跨度只留聚合态(净值、持仓、pending 指令、择时状态机状态、逐日仓位标记)
- **无缓存的影响**:每次回测都真实访问 MySQL——块间 BETWEEN + 分片已把扫描控制在块粒度;实施前对 `mkt_equd_adj`/因子表做 EXPLAIN 压测,必要时建议数据侧按月分区(§10-⑥);Parquet 缓存作为后续优化项见 §11

### 3.3 指标模板(数据导入后即插即用)

果仁 7 指标(MA[5,60]、MACD[12,26,9,零轴]、DMA[5,60,20]、TRIX[120,5]、MAVOL[5,60]、BIAS[1,20,-10,10]、PE[15,30])本质都是"衍生字段 + 条件"。引擎不实现指标计算;待衍生字段入库后,指标模板=预置 rules 组合,默认参数引用果仁值。交叉语义(金叉死叉)由 op 扩展 `'xup'/'xdn'` 表达(常量追加,无迁移)。

## 4. 参数接口

```ts
// ── 择时(新增,可选;模型 Ⅰ/Ⅱ 引擎通用)──
interface StrategyTimingOverlay {
  index: 'sse' | 'hs300' | 'csi500';   // 默认 sse(000001 上证,复用 BENCHMARKS)
  rules: FieldConditionRule[];         // 1~3 条,逐日投票
  enterVotes: number;                  // 熊转牛所需牛票数,-1=全部;默认 -1
  exitVotes: number;                   // 牛转熊所需熊票数,-1=全部;默认 -1
  bearPositionPct: number;             // 熊市总仓位 0~100 整数;默认 0
}
// ── 交易模型扩展(模型 Ⅱ 独立引擎)──
rebalanceIntervalDays: 0              // 0 = 路由到模型 Ⅱ 引擎;≥1 = 模型 Ⅰ(v3 内核)
positionDeviatePct?: number           // 模型 Ⅱ 必填:仓位偏离带宽 %(如 20)
// 触发域 = securityIds(复用,上限重估为 3000,见 §5.4)
```

校验:`assertTimingOverlay`(index 枚举;rules 1~3;table 须白名单日期表且在开放清单内;field 白名单;bw 时 low<high;votes ∈ {-1}∪[1,n];bearPositionPct 整数 0~100);路由层:`rebalanceIntervalDays=0` 时路由模型 Ⅱ 引擎并要求 `positionDeviatePct`(5~50)。展示 `describeTimingOverlay`/`describeTradingModel` 确认门与卡片同源。

## 5. 引擎改造

### 5.1 共享构件库(新建,两引擎引用,通用逻辑只写一份)

| 构件 | 内容 |
|---|---|
| `field-condition.ts` | 字段条件判定(op 判定、bw、缺值弃权)+ `TIMING_OPS` 白名单常量 |
| `timing-state.ts` | 择时投票状态机(enterVotes/exitVotes/初始牛)→ 逐日目标仓位序列 |
| `account.ts` | 资金账户:现金/持仓/T+1 锁定/整手取整/万三费用(从 v3 语义抽取) |
| `timing-scale.ts` | 择时缩放执行:目标市值差 >1% 权益才动作;减仓优先卖未锁定仓 |
| `stats.ts` | 三件套:仓位分布/持股时间占比/踏空归因 |

构件全部带单测;两引擎**禁止各自复制实现**。

### 5.2 模型 Ⅰ:v3 内核叠加择时(主循环不动)

挂载点:① 预取(L253-259 基准旁)按 rules 预取指数字段序列;② 信号阶段(L438-450)逐日算 `pendingExposure`;③ 执行阶段(L365 guard 之外)择时缩放块;④ 调仓目标市值(L372)乘暴露系数。容量护栏沿用(≤550 次/候选 ≤1500)。分块流水线**不**改造进 v3——模型 Ⅰ 保持现行为,待模型 Ⅱ 引擎验证后按需迁移(对拍保证等价)。

### 5.3 模型 Ⅱ:新建独立触发引擎

- 骨架:N 交易日分块流水线(§3.2)上跑同样的 执行→结算→信号 逐日循环,复用 §5.1 全部构件
- **买入触发**:触发域内股票逐日判 entryFilters → 次日开盘按理想仓位买入(整手、现金不足缩股)
- **仓位偏离带**:收盘后 |持仓市值/权益 − 目标总仓位| > `positionDeviatePct%` → 生成再平衡指令拉回带宽(择时目标仓位即目标总仓位,天然串联)
- **卖出触发**:sellRules 逐日(语义同 v3)
- 新增参数:`rebalanceIntervalDays=0` 路由标识、`positionDeviatePct`

### 5.4 护栏重估(模型 Ⅱ 引擎)

| 项 | 模型 Ⅰ(v3 沿用) | 模型 Ⅱ |
|---|---|---|
| 监视范围 | 调仓日候选并集 ≤1500 | **触发域 ≤3000(初定,压测定稿)**:预声明的逐日监视名单,不声明=全市场逐日评估不可控 |
| 行为上限 | 调仓次数 ≤550 | **单日买入笔数上限 + 总换手率上限**(压测定稿):触发式没有"调仓次数",压力来自实际成交笔数 |
| 年限 | 受调仓次数限制(约两年) | 内存有界后受 MySQL 查询时长约束;目标 10 年 × 全市场(压测定稿) |

### 5.5 统计三件套(共享构件,卡片新增)

仓位分布(各档天数)、持股时间占比(暴露>0 天数占比,对齐果仁 open-rate)、踏空归因(基准 Top10 单日涨幅中暴露<50% 的清单:日期/涨幅/当日仓位)。

## 附录 A:择股设置的智能体对话对应(现状,本期不改造)

### A.1 链路(已上线,4 步)

用户一句话 → GLM 调 `list_factor_tables`/`list_factor_fields` 查字典 → GLM 组装参数 → 确认门弹窗(用户回"确认"执行 / "授权调优"多组对比)。

### A.2 果仁表单 → AlphaSage 参数(逐项,字段名为实际代码字段)

| 果仁表单控件 | AlphaSage 参数 | 取值 |
|---|---|---|
| 股票池下拉 | `securityIds` | `string[]`,如 `["000002.XSHE"]`;空=全市场;上限 5000 |
| 筛选条件行(指标+比较符+值) | `entryFilters` | `{table, field, op, value}`;op 仅 `">"` `"<"` 两种;value 数字 |
| 排名条件行(指标+次序+权重) | `sortFactors` | `{table, field, direction, weight?}`;direction `1`=值大优 `-1`=值小优;weight 全传或全不传 |
| 卖出条件 | `sellRules` | kind 六选一:`field`/`stop_profit`/`stop_loss`/`max_drawdown_from_entry`/`max_hold_days`/`rank_out` |
| 调仓周期(交易日) | `rebalanceIntervalDays` | 1–250,**必填**;本方案扩展 `0`=触发模式(模型 Ⅱ 引擎) |
| 调仓时点 | `executionTiming` | `0`=开盘价,`1`=收盘价 |
| 最大持股股票数 | `maxPositions` | 1–100,默认 10 |
| 个股最大买入仓位 | `idealPositionPct` | 缺省=100/maxPositions |
| 回测收益基准 | `benchmark` | `"hs300"` / `"csi500"` / `"sse"`,默认 hs300 |

字段名出处:table/field 只能取 `SQL/` 字典已导入表(如 `equ_factor_obos.REVS20`=20日动量、`equ_factor_obos.RSI`、`equ_factor_obos.HSIGMA`=历史波动),GLM 经字典工具发现,不许编。

### A.3 完整例子

用户:"2024 年,每 20 个交易日调仓,选 RSI 低于 30 且 20 日动量最大的前 10 只,涨 20% 止盈"

```json
{
  "startDate": "20240101", "endDate": "20241231",
  "rebalanceIntervalDays": 20, "maxPositions": 10,
  "entryFilters": [{ "table": "equ_factor_obos", "field": "RSI", "op": "<", "value": 30 }],
  "sortFactors": [{ "table": "equ_factor_obos", "field": "REVS20", "direction": 1 }],
  "sellRules": [{ "kind": "stop_profit", "pct": 20 }],
  "benchmark": "hs300"
}
```

### A.4 无对应的三处(可选二期)

系统股票池目录(17 个)、比较符 `eq`/`bw`(择时规则已含 `bw`,选股 entryFilters 仍是 `>`/`<`)、不卖条件(优先级高于卖出)。

### 15.3 与方案的差异

1. 构件库未拆独立 `src/core/shared/` 目录——字段条件/状态机/统计落在 `timing.ts`（果仁语义等价物），账户执行逻辑保持各引擎内联（两引擎语义已由构件单测+对拍覆盖；后续如出现第三处复用再抽取）
2. 模型 Ⅱ 引擎 v1 为逐日截面直查 MySQL（未做块级 BETWEEN 聚合）——内存已按"触发后懒加载行情"天然有界，块级聚合留作性能优化项
3. `weightMode`/周月周期/公式模式等远期项按 §11 边界未实现；`fst_total` 键形态适配与 `'xup'/'xdn'` 操作符留待衍生字段入库
4. Parquet 缓存按用户决策移出本方案（部署形态定后上，预取接口位置不变）
