# 权重与仓位函数化 功能清单

> 更新:2026-10-17 · 状态:设计定案（ADR-0005），待开工
> 背景:因子权重（`sortFactors[].weight` 静态数字列）与持仓仓位（等权）由引擎硬编码；《大盘择时重构方案》§1.2 的"模型 Ⅲ 定期轮动+公式权重"（果仁原文"股票仓位权重由公式决定"）一直标待实现。本次把两者统一**函数化**：GLM 传函数名+参数，后端注册表解析执行，每次调仓求值。
> 依据:ADR-0005《权重与仓位函数化》、GLOSSARY.md「权重函数」词条簇、grill 定案（2026-10-17，三轮）。

---

## 功能条目

### 1. 因子权重函数（静态数字列退役）

**用户能做的事（对话示例）**:"因子权重按常数比例，REVS20 给 0.5、Volume1M 给 0.3、BIAS60 给 0.2"——模型传 `weightFn: { name: "constant", params: { weights: [0.5, 0.3, 0.2] } }`，按因子登记顺序对位。

**语义**:每次调仓时求值（当前是回测全程一个静态数）；参数只放策略旋钮，因子截面数据由引擎按"缓存→数据库"供给（数据库是因子值唯一事实，不存在计算因子）。

**实现要点**:后端函数注册表（core 内置，代码维护）；`constant` 因子权重版 = 现状静态 weight 列的内化，缺省（无 weights）= 1/N 等权——现状行为零变化。

**量**:含在注册表 1 天内。

### 2. 仓位函数（金额字典）

**用户能做的事（对话示例）**:"第一名买 40%、第二名 30%、第三名 20%、第四名 10%"——模型传 `positionFn: { name: "constant", params: { proportions: [0.4, 0.3, 0.2, 0.1] } }`，按名次对位。

**语义**:每次调仓时，函数接收本期拟买入股票（含名次/得分）与**当期剩余资金**，输出**各股买入金额字典**。关键约束:GLM 生成参数时不知道运行期的股票与现金，所以参数只能是份额比例，金额是函数在每期的换算输出（比例 × 当期剩余现金）。

**实现要点**:缺省（无 proportions）= 等权金额——现状持仓等权内化为同一函数；对位宽容规则:数组短于买入数→剩余条目平分剩余比例、长于→截断、总和<1→差额留现金、>1→归一化到 1。

**量**:含在注册表 1 天内。

### 3. 函数注册表

**说明**:权重函数与仓位函数的唯一登记处（core 代码内置，加函数=开发发版）。每个函数声明:名称、中文说明、参数 schema（供工具 schema 与参数校验）。GLM 只传 `{name, params}`，后端解析执行——模型输出永远不是代码，无 eval/沙箱问题。

**参数简洁原则（策略旋钮）**:函数参数只承载策略选择（比例数组、衰减系数），一切数据类输入（因子截面、IC、名次、剩余资金）由引擎上下文供给；将来 `ic_weight` 这类函数的参数可以完全为空——参数越少，GLM 出错越少。

**量**:0.5 天。

### 4. 独立校验器（金额防线）

**说明**:仓位函数输出金额后、下单前过独立校验器:① 整手（向下取整到 100 股）② 现金充足 ③ 仓位上限。失败语义 = **逐条修正而非整期硬拦**:整手向下取整、现金不足从后往前剔除，输出"修正后金额 + 违规清单"进回执——与现状执行层语义一致（T+1/整手/费用本来就有），只是把检查前置显性化。

**量**:0.5 天。

### 5. 确认门与卡片展示

**说明**:确认门追加「权重函数：常数比例 [0.5, 0.3, 0.2]」「仓位函数：常数比例 [0.4, 0.3, 0.2, 0.1]」两行（函数中文名+参数）；卡片 params 透传同样内容；校验违规清单进工具回执。函数名录与说明写进工具 schema description，GLM 照名录选择。

**量**:0.25 天。

### 6. 兼容层（旧配置复现）

**说明**:旧 config 的静态 `sortFactors[].weight` 列由兼容层自动翻译成 `constant` 调用——历史策略复现逐位不变；新对话/新 config 一律函数形式，schema 不再出静态 weight 字段。

**量**:0.25 天。

### 7. IC 因子权重函数（ic_weight）

**用户能做的事（对话示例）**:"因子权重按最近 20 天的 IC 加权"——`weightFn: { name: "ic_weight", params: { icWindow: 20 } }`。

**语义**:每个排序因子取滚动窗口内的日频 Spearman 秩相关（因子截面 vs 次日收益）均值，**正部归一化**定权（负 IC 因子权重 0）。防未来:决策日 D 的窗口最后一对配对 = (D-1 因子值, D 收盘收益)，T+1 开盘执行时序合法。`icWindow` 是策略旋钮（可调）。

**实现要点**:引擎上下文新增 `icByFactor`（引擎算好喂给函数，函数本身只做归一化）；数据 = 窗口内每日因子截面 + 日收益（缓存→数据库，每次决策日预取一次复用）。

**量**:1 天（含每日截面预取管线）。

### 8. 因子仓位函数（factor_position）

**用户能做的事（对话示例）**:"用 BIAS20 定仓位，站上 20 日线的才买，偏离越大买越多"——`positionFn: { name: "factor_position", params: { factor: { table: "equ_factor_obos", field: "BIAS20" } } }`。

**语义**:**正部比例加权**——候选股按定权因子的截面值 `仓位_i ∝ max(值_i, 0)`，归一化到剩余资金；全部 ≤0 → 该期空仓（合法，回执告警）。"站上 MA20"即用乖离率因子 BIAS20 > 0 表达，引擎不必算均线。

**实现要点**:参数是**因子引用**（table.field，过字典白名单校验），截面由引擎按现有取数路径预取（缓存→数据库，因子值唯一事实不变）喂进 `PositionCtx.sizingSection`；与大盘择时的分工不变——指数级总仓位语义走择时，仓位函数只做个股级。

**量**:0.5 天。

### 9. 决策日求值语义（两函数共用）

**说明**:信号（IC、MA）每天自然变化，但引擎**在交易决策日求值**——调仓模式的决策日 = 调仓日（事先已知），条件触发模式的决策日 = 触发日（运行时确定），ctx 以决策日为端点惰性回取窗口数据。信号每天变 ≠ 每天交易；要日频调整走 `rebalanceIntervalDays=1` 或触发模式。

**量**:0（机制性说明，成本含在 7/8 中）。

## 验收口径

1. **内化等价性**:`constant` 因子权重 [0.5,0.3,0.2] 与旧静态 weight 列同配置回测结果**逐位一致**
2. **缺省回归**:不传任何函数 → 等权路径与现状逐位一致
3. **仓位换算**:proportions [0.4,0.3,0.2,0.1] × 当期剩余现金 → 金额字典 → 整手修正后成交，违规清单出现在回执
4. **对位规则**:短数组剩余平分、长截断、总和>1 归一（单测覆盖）
5. **兼容复现**:历史策略（静态 weight 列）经兼容层回测结果不变
6. 既有测试零回归
