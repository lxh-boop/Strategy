# 仓位维持与涨跌停顺延 功能清单

> 更新:2026-10-22 · 状态:已实施待验收（代码在工作区，ADR-0008）
> 背景:掘金交叉验证发现引擎默认执行语义与主流平台存在两处行为差异——择时缩放块（保持满仓）在 2025 有色段贡献约 36 个百分点收益差、涨跌停顺延为自研超出掘金默认撮合的真实度增强。按 ADR-0008 参数化：**掘金对齐语义为默认，自研增强为可选参数**。
> 依据:ADR-0008、离线全路径重放实测（2026-10-21，同数据同规则双配置对照）。

## 功能条目

### 1. 仓位维持（keepFullyInvested）

**用户能做的事（对话示例）**："这个策略要始终保持满仓，有股票触发卖出就把钱立即买回其他持仓"。

**语义**:`true` = 每个交易日收盘后将总仓位维持在全额暴露——无择时叠加时即保持满仓，卖出规则触发的现金**当日按持仓市值占比整手回补**剩余持仓（±仓位带宽内不动，涨跌停/停牌顺延）；`false`（默认）= 掘金对齐语义：卖出现金保留至下一调仓日再投资。

**边界**:仅在**无择时叠加**时生效——择时叠加的仓位调整依赖该块执行，有叠加时块无条件运行；全仓清空（无持仓）时也不回补（现金等调仓日，与掘金一致）。

**实现要点**:策略回测引擎执行阶段择时缩放块加门控（strategy-backtest.service.impl.ts:652 附近）；参数随确认卡与卡片 config 持久化（保存的策略重跑自包含）。

**量**:0.5 天（已实现）。

### 2. 涨跌停顺延（limitUpDownSkip）

**用户能做的事（对话示例）**："回测考虑真实约束，涨停别追、跌停卖不出就顺延"。

**语义**:`true` = 执行价触及涨停（≥昨收×1.0999）的候选**不买入**、触及跌停（≤昨收×0.9001）的持仓**不卖出**（顺延下一交易日，规则当日仍触发则次日再判）；`false`（默认）= 涨跌停价照常成交（掘金对齐语义）。

**说明**:此项是自研**超出掘金默认撮合**的真实度增强（真实市场一字板买不进、跌停卖不出）；默认关闭以保证跨平台对照时默认口径一致，开启即增强回测真实度。

**实现要点**:执行循环三处门控——卖出跌停顺延（impl:646）、买入涨停跳过（impl:723）、择时块 canSell/canBuy（impl:664-668）。

**量**:0.25 天（已实现）。

### 3. 默认值决策（随 ADR-0008 定案）

两参数默认均取**掘金对齐语义**：当前无存量用户与历史策略，默认口径 = 跨平台对照口径；开启参数即自研的真实度/收益增强项，不是背离。

## 验收口径

1. `keepFullyInvested` 缺省（false）：BIAS20 触发卖出的现金**无择时加仓 trade**、剩余持仓份额不变；
2. `keepFullyInvested=true`：卖出当日出现「择时加仓」trade、只买剩余持仓（被卖票不回补）；
3. `limitUpDownSkip` 缺省（false）：开盘涨停的候选照常建仓；
4. `limitUpDownSkip=true`：开盘涨停的候选跳过（无调仓建仓 trade）；
5. 两参数随确认卡展示、随策略 config 持久化（保存的策略重跑自包含）；
6. 掘金对照矩阵：自研 `keepFullyInvested` ↔ 掘金 main.py `TIMING_TOPUP`、自研 `limitUpDownSkip`（关）↔ 掘金（撮合不判涨跌停）——同置后收益差收敛至执行层残差（预期几个点）。
