## 二、雪球结构：四环三刀

```
GLM 慢（限流/大上下文，不可修） → 前端 90s 无事件判死 → 用户重发 → 并行双图 → 配额烧穿 429 → 更慢
        ①误杀                    ②重发动机            ③重发后果
```

慢本身不可修（限流在智谱侧）；治理对象是"慢被误判成死"和"慢的后果被放大"。

## 三、三个断点的实现

### 3.1 第一刀：keepalive 保活帧——慢不再被误判成死

**位置**：`langgraph-agent.service.ts` → `runGraph()`（拍板放 agent 层而非 controller——"工具执行慢和 GLM 回答慢放一起处理"；这里才看得见"谁在跑"，controller 只看得见"请求没结束"）。

**实现**：图执行入口起 `setInterval(15s)`，经**与工具进度事件同一条 onProgress 管道**发 `{type:'keepalive'}`；图收尾（成功/失败/挂起确认）在 `finally` 清除定时器。仅流式路径启用（同步 `reply()` 无 onProgress 可发）。

**前端为什么零改动**（两处口子当时就留好了）：

- `api.ts` 的 `armIdle()` 在每次 `reader.read()` 前重置 90s 空闲计时——**收到任何字节都算活着**，keepalive 帧照常喂；
- 解析器 `handleLine` 对不认识的帧推给调用方，`useConversations` 的分支不匹配即忽略，无 UI 变化。

**分层关系**：keepalive = 报活（无内容语义）；引擎进度事件（`strategy-backtest.service.impl.ts` 信号预计算每 25 调仓日一批、行情按 QUOTE_BATCH 批）= 报内容（前端实时步骤展示，含批次详情滚动上屏）。两层并存，覆盖互缺：进度事件填不满 GLM 思考的空窗，keepalive 给不了前端可展示的信息。后端进程真死时心跳停、看门狗照报（反向保护保留）。

### 3.2 第二刀：前端超时不撤回——消灭重发动机

`useConversations.ts` 的 catch：**TIMEOUT 与 ABORTED 同待遇**——不回滚乐观消息，toast 如实告知：

> "连接超时，但这条消息已送达、服务端仍在处理，结果稍后会出现在会话中（无需重发）"

依据：消息真实相在库里不在连接里（图跑完 persist 照执行），撤回 = 制造"消息消失"假象 + 暗示用户重发。前端本就无自动重发逻辑（碰巧符合期望），此刀修的是撤回行为与文案误导。

### 3.3 第三刀：消息级并发闸——重发翻不起浪

`langgraph-agent.service.ts` 新增 `inflightRuns: Set<会话id>`（与既有 `inflightResumes` 并列）：

- `runGraph` 开头：**新消息**（`!pendingThread`）撞上在途会话 → 409 `CONVERSATION_BUSY`「上一条消息还在执行中…无需重发」；
- 图收尾 finally 必删；409 必须抛在下方吞异常的 try **之外**（catch 会把一切异常吞成文本回复），ApiException 才能穿透为 SSE error 帧；
- **确认门答复不查此闸**（挂起的确认必须可答，否则确认门死锁），其防重复由 `inflightResumes` 负责（对照见[确认门文档 §2.4](确认门批准实现.md)）；
- 效果：手快连发/超时重发不再并行起第二个图——配额单份，不会滚进 429。

### 3.4 兜底：失败可见

图执行失败（Recursion limit / 429 / MySQL 502）走 `errorReply` 转失败文案正常返回 → persist 落库为普通一轮。`llmErrorText` 对 429/速率限制单独措辞："模型服务限流，请稍后重发这条消息"（原文案"请充值或检查 ZHIPU_MODEL 配置"对暂时性限流是误导）。

## 四、各环对照

| 环节 | 机制 | 位置 |
|---|---|---|
| ①慢被误判死 | keepalive 15s/帧 | `runGraph` 定时器 + `api.ts armIdle` |
| ②重发动机 | 超时不撤回 + 诚实文案 | `useConversations` catch |
| ③重发→双跑 | inflightRuns 409 | `runGraph` 入口 |
| ③'确认重复恢复 | inflightResumes 409 | `runGraph` 入口（详见[确认门文档](确认门批准实现.md)） |
| ④失败隐形 | errorReply 落库 + 429 文案 | `errorReply`/`llmErrorText` |

**测试**：`test/core/implementations/langgraph-agent.keepalive-gate.spec.ts`（假 app.invoke 替身，不建真图不调真模型）——同会话并发 409 且不打进图 / 出结果放行 / 跨会话互不影响 / keepalive 定时发+收尾即停+同步路径不发。
