> **版本**：v1.0（2026-10-15 初版）
> **状态**：已实施并推送（确认门主体 d464a16 / 入口授权 b817abe / 防重入闸 67d1d37 / 快检区间校验 50d55b56；本轮无代码变更，仅文档化）
> **关联文档**：[超时重发链路治理](超时重发链路治理.md)

## 一、基座：LangGraph interrupt + MemorySaver

- **interrupt = 直接结束 + 凭存档恢复**，不是挂起：confirm 节点内 `interrupt(payload)` 抛 `GraphInterrupt` → 图立即终止，状态存入 MemorySaver（按 thread_id）；
- **恢复 = confirm 节点从头重跑 + interrupt 序号答案回放**——节点必须幂等（零副作用），这也是"确认与执行拆节点"（d464a16）的动机：confirm 只做归一化/白名单快检/interrupt，执行在 tools 节点；
- `guard()` 必须 rethrow `GraphInterrupt`（它是靠抛错实现的暂停信号，吞掉 = 确认门失效）。

## 二、三节点结构

```
agent ⇄ confirm ⇄ tools
```

- **agent**：GLM 决策，发工具调用；
- **confirm**：`run_strategy_backtest` 的调用先进这里。`execConfirmBacktest` 做参数归一化 + 快检（表/字段白名单、交易日覆盖区间——越界提案确认前打回模型自纠，用户不再白确认一轮）+ 逐组 `interrupt(参数九项)`，把格式化后的参数弹给用户；
- **tools**：纯执行，逐组判权——`confirmedCalls` 放行 / `rejectedCalls` 回执透传 / delegate 本轮全放行。拆节点修掉同批多回测逐组确认 O(K²) 重复执行。

## 三、批准的决策路由（`resumeConfirm`）

会话挂起期间（`pendingConfirms: Map<会话id, threadId>`），下一条用户消息是**决策不是新提问**：

| 用户回复 | decision | 效果 |
|---|---|---|
| `确认` / `确认执行` | approve | 本组放行执行 |
| `授权调优` | delegate | 本次图执行内所有回测组免确认 |
| **其余一切** | feedback | 该组取消，文本原样交模型消化（可能重提案→再次 interrupt） |

**语义解释只认精确匹配词，不做模糊匹配**（2026-10-13 拍板）。入口同理：消息精确等于"授权调优"→ 初始状态 `backtestDelegated: true`（入口授权）。

恢复动作 = `app.invoke(new Command({ resume: decision }), { configurable: { thread_id }, recursionLimit: 15 })`——同一 thread 上继续。图正常收尾时 `collectReply` 清挂起映射；`__interrupt__` 存在则记 `pendingConfirms` 并返回参数确认文案（前端 `parseConfirmGate` 逐行解析成确认弹窗）。

## 四、两道闸与批准的关系

| 闸 | 集合 | 拦谁 | 放谁 | 来源 |
|---|---|---|---|---|
| 恢复防重入 | `inflightResumes` | 挂起确认的**重复恢复**（恢复执行中再点确认/超时重发答复——会与第一次并行各跑一遍引擎，双倍打库、两份卡片） | 首次恢复 | 67d1d37，10-13 |
| 消息级并发闸 | `inflightRuns` | 在途会话的**第二条新消息** | 首条消息 + **全部确认门答复** | b6f86ac，10-15 |

两闸条件互斥（`pendingThread` 存在与否），缺一不可：并发闸豁免答复路径（挂起的确认必须可答，否则确认门死锁）；恢复闸拦恢复路径内的重复（并发闸够不着）。

## 五、失败语义：fail-open

恢复过程 GLM 报错 → 清掉 `pendingConfirms` 退回普通对话（不把会话卡死在确认模式），错误原样上抛给 `errorReply` 落库告知用户。进程重启 = `pendingConfirms` 丢失 = 挂起确认作废，用户重发回测请求即自愈（进程内存方案的既定代价；MySQL checkpointer 在记账清单）。

## 六、记账未做

- **文本=取消陷阱**：用户在门里回自由文本（如"每月 21 个交易日"，本意 approve）→ 按 feedback → 取消 → 模型重提案（可能改坏参数，10-15 实证自编单股票池）→ 第二次确认门。候选方向：门文案明示"同意请回复确认，修改请说要改什么"、或答复数值与提案一致时智能判定。**未实施，等拍板**；
- **拒绝循环撞 recursionLimit 15**：模型传错参数（表名错/区间越界）→ 拒绝回执 → 重试 → 再拒绝，烧光 15 步整轮报废（15:56:39、16:17:05 两次实证）。方向=同参重复拒绝设上限或提高 recursionLimit。
