## 一、回测参数确认弹窗（确认门）

### 1.1 为什么弹出

后端模型发起 `run_strategy_backtest` 时，不直接执行：confirm 节点把参数格式化成**锚定文案**（`将按以下参数执行策略回测：` + `- 回测区间：xxx` 逐行）作为普通 agent 消息返回并落库，图在该处 interrupt 挂起等用户批准。前端扫**当前会话最后一条消息**识别这个提案，弹窗让用户按钮化决策——"按钮化决策替代自然语言猜测"（e5ddd04），用户不再需要猜该回什么词。

### 1.2 弹出条件（`gateVisible`，四个同时满足）

| 条件 | 代码 | 说明 |
|---|---|---|
| 末条消息是提案 | `parseConfirmGate(末条.bubble)` 非空 | 正则锚定 `/^将按以下参数执行(策略\|等权)回测：/` + `- 标签：值` 行（与服务端 `formatConfirmText` 文案强约定） |
| 不在生成中 | `!typingHere` | 流式回复进行中不弹，等 final |
| 未被关过 | `!gateClosed` 且指纹不在 `dismissedRef` | 见 1.4 防打扰 |
| 无请求在途 | `!loading` | |

### 1.3 弹出之后的处理

| 用户操作 | 前端动作 | 后端效果 |
|---|---|---|
| 点 **确认执行** | `gateAct("确认")`：关弹窗 + 把"确认"二字作为普通消息发送 | `resumeConfirm` 精确匹配 → approve → 放行本组执行 |
| 点 **授权调优** | `gateAct("授权调优")` | delegate：本次图执行内所有回测组免确认 |
| 输入框输入后发送/回车 | `gateAct(自由文本)` | 不匹配任何精确词 → feedback：该组取消，文本交模型消化（可能重提案 → 再次弹窗） |
| 点右上角关闭 | `closeGate()` | 只关弹窗，**不发送任何消息**，门继续挂起 |

注意第三行：输入框里的自由文本 = feedback = 取消，这是已记账的"文本=取消陷阱"（见确认门文档 §6）。

### 1.4 防打扰指纹（同一条消息只弹一次）

- 会话/消息数变化会重置 `gateClosed` 布尔，导致**挂在会话末尾的旧提案反复弹窗**（2026-10-13 实证：RSI 回测回复结尾带"授权调优"邀请，一整天每次进会话都跳）；
- 现行方案：按"会话id + 消息数 + 末条前80字"生成指纹 `gate:lastKey`，关过的进 `dismissedRef`（Set）——**指纹不随重置消失，关过的消息永不再弹**；模型给出新回复（指纹变化）才重新触发。

## 二、优化建议弹窗

### 2.1 为什么弹出

模型按系统提示词的回复规则，在失败回复/多方案对比的结尾给出优化建议并**邀请用户回复"授权调优"**（话术锚定，如"也可直接回复'授权调优'让我继续"）。前端用规则匹配识别这个邀请，弹窗把"授权调优"从一句话变成一个按钮 + 附带原文展示，省去用户手打。

### 2.2 弹出条件（`optimizeVisible`）

- 末条是 agent 消息，且 `parseOptimizeInvite` 命中：`bubble.includes("授权调优") && /建议|方向|对比/`（规则匹配替代自然语言猜测）；
- **与确认门互斥**（`!gateParams`——一条回复不会既是提案又是建议邀请）；
- 不在生成中、未被关过（同 1.4 指纹 `opt:lastKey`）、无请求在途。

### 2.3 弹出之后的处理

| 用户操作 | 前端动作 | 后端效果 |
|---|---|---|
| 输入框补充要求后发送 | `optimizeAct(文本)`：关弹窗 + 发送 | 作为普通消息进图（模型带上下文执行） |
| 点 **授权调优** | `optimizeAct("授权调优")` | 入口授权 → 本轮回测免确认 |
| 关闭 | `closeOptimize()` + 指纹 | 不发送，建议留 bot 消息里随时可看 |

## 三、破坏性操作确认（ConfirmModal）

删除会话 / 清空会话前弹出，全站统一 `components/ui.tsx` 的 `ConfirmModal`。确定才执行 DELETE/POST clear，取消无副作用。与上面两类不同：它是纯前端拦截，不经过后端确认门。

## 四、弹窗的共同生命周期

- **触发源只有"最后一条消息"**：弹窗状态是消息的衍生品，不是独立事件流——消息落库后刷新/重进会话，满足条件照样弹（指纹拦重复）；
- **关闭分两层**：`gateClosed`/`optimizeClosed` 布尔随新消息/切会话重置（`useEffect` 依赖 `current.id` + `messages.length`）；`dismissedRef` 指纹永久记忆，保证同一条消息终身只打扰一次；
- **按钮 = 发送固定文案**：所有决策按钮最终都走 `onSubmit(固定文本)` 复用普通发送链路，后端无需独立 API——这是"按钮化决策"与后端精确匹配词的契约。
