> 版本 v1(2026-10-15)· 状态:**待评审**

## 2. P0-1:每期持仓明细(果仁「每日选股」的历史版)

### 功能
回测卡片新增「每期持仓」表格(历史持仓详情的姊妹面板):每期列出**实际持有的股票清单 + 各股期间收益 + 权重**,以及「最新调仓指令」「最近卖出的股票」两个子视图(对应果仁同名标签)。

### 实现(数据引擎已齐,纯聚合输出)
- 契约层新增 `buildPeriodHoldings(trades, tradeDates, periodStarts, quotes)`:按期切片交易流水,输出每期 `{seq, 持仓清单:[{code, 名称?, 股数, 期末价, 期间收益%}], }`
- 个股期间收益 = 期末价/期初价−1(期初=该股进入持有期的首个执行价;新增股票用买入价)
- 卡片新增 `periodHoldings`(每期持仓清单)与 `latestOrders`(最新调仓指令:最后一期的全部交易)、`recentSold`(最近卖出的股票)
- 前端:历史持仓详情表格下加同款 mini-table 三子标签(与果仁一致)
- 量:数据全在内存交易流水里,**零新增查询**

工作量:0.5~1 天(含前端三个子标签)。

## 3. P0-2:排名分析(因子有效性评估,果仁核心分析能力)

### 功能(果仁面板原文口径,已逆向)
对**一个排序因子**,把全池股票按因子值分成 N 段,逐段回测对比:
- 分段年化收益对比表/图(单调性一目了然)
- **因子 IC 均值、IC 为正的概率、因子 IR、排列单调性(r2_score)**
- 因子历史 IC 曲线、IC/IR 衰减(按持有期)
- 市值分位图(因子是否只在小市值有效)
- 多空收益(第 1 段做多 − 末段做空)

### 实现(新建分析服务,复用引擎取数与模拟)
- 新建 `factor-analysis.service.ts`:`runRankAnalysis({ sortFactor, pool, segmentCount, intervalDays, startDate, endDate, benchmark })`
- 流程:① 逐调仓日取因子截面(复用 readFactorSection)→ 按值分 N 段;② 每段构造一个虚拟组合(段内等权),复用模型 Ⅰ 内核的执行/结算/资金账户逻辑跑 N 条净值;③ 计算 IC:每期段别与下期段收益的 Spearman 相关 → IC 序列 → IC 均值/正概率/IR;④ 单调性 = 分段收益排名与段序的 r2
- 段内组合模拟**直接复用模型 Ⅱ 引擎的逐日循环**(段=一个 securityIds 池,sortFactors 传同因子)——串行 N 次调用,无新内核
- 前端:新卡片类型 `rankAnalysis`(分段收益表 + IC 曲线 + 指标格),GLM 工具新增 `run_rank_analysis`
- 数据:因子截面 + 行情,现有 11 表够用
- 性能:N 段 = N 次回测,建议 N≤10、区间 ≤3 年(容量护栏沿用)

工作量:2~3 天(分析服务 1 天、卡片/编排 1 天、测试冒烟 0.5~1 天)。

### 模块落位(文件级)

**后端新建 2 文件(factor-agent-server)**

| 文件 | 内容 |
|---|---|
| `src/core/factor-analysis.service.ts`(契约层) | 纯函数:`spearmanOnCrossSection`(单日两截面秩相关,公共股票缺值剔除)、`icForPeriod`(因子分位 vs 下期收益秩相关 = IC)、`monotonicityR2`(段序 vs 段收益秩相关的 r²);类型 `RankAnalysisInput/Output`;抽象类 `FactorAnalysisService` |
| `src/core/implementations/factor-analysis.service.impl.ts`(取数编排) | `runRankAnalysis`:逐调仓日 `readFactorSection` 取截面 → `rankUniverse` 分 N 段 → 每段等权虚拟组合下期收益(`readQuoteSeries` 区间行情)→ IC 序列/单调性/分段表;白名单复用 `assertWhitelist` |

**接线 3 处(照抄现有模式)**

| 位置 | 改动 |
|---|---|
| `core.module.ts` | 注册 `FactorAnalysisService`(照抄 StrategyBacktestService 两行) |
| `tool-specs.ts` | 新增 `run_rank_analysis` 工具 schema(因子/区间/分段数 N≤10/股票池;参数纪律沿用回测规则) |
| `langgraph-agent.service.ts` | 工具执行器(assert → preflight → 确认门 → 调用)+ 提示词补排名分析规则 |

**前端 3 处(factor-agent-react)**

| 位置 | 改动 |
|---|---|
| `types.ts` | 新增 `RankAnalysisCard`(CardBase 扩展) |
| `ChatPage.tsx` | 新卡片分支:四指标格(IC 均值/正概率/IR/单调性)+ 分段收益表 + IC 曲线 |
| `global.css` | IC 曲线与色阶样式(沿用 --up/--down) |

### 算法口径(与果仁对齐)

| 果仁指标 | 计算式 |
|---|---|
| 因子 IC 均值 | 各调仓日 IC(因子分位 vs 下期收益的 Spearman)均值 |
| IC 为正的概率 | IC>0 的期数占比 |
| 因子 IR | IC 均值 ÷ IC 标准差 |
| 排列单调性 | 分段收益排序与段序秩相关的 r²(0~1,果仁原文口径) |
| 多空收益 | 第 1 段收益 − 第 N 段收益 |
| 市值分位 | 各段持仓的市值中位数分位分布(市值字段取字典表) |

## 4. P0-3:因子相关性矩阵

### 功能
对一批候选因子,计算**两两相关系数**(按日截面秩相关),输出对称矩阵热力图——多因子组合前判断冗余。

### 实现
- 新增 `run_factor_correlation({ refs: [{table,field}...], pool, intervalDays, startDate, endDate })`
- 流程:逐调仓日取各因子截面(与回测信号预取同通道)→ 两两 Spearman 秩相关 → 对称矩阵;因子 ≤10 时 45 次相关计算,纯内存
- 前端:新卡片 `correlationMatrix`(表格 + 色阶),GLM 工具 `run_factor_correlation`
- 与排名分析共用取数骨架,建议同一批次实现

工作量:1 天(与 P0-2 共享骨架时 0.5 天)。

### 模块落位(文件级)

- 契约与实现**并入** `factor-analysis.service.ts` / impl(与 P0-2 同文件):`runFactorCorrelation` + `CorrelationInput/Output` 类型
- 算法:逐调仓日 `readFactorSection` 取各因子截面 → 公共股票集上两两 Spearman 秩相关 → 对全部调仓日求均值 → 对称矩阵;因子 ≤10(45 对),纯内存
- 编排接线:同批次注册于 `core.module.ts`;`tool-specs.ts` 增 `run_factor_correlation`;前端新增 `CorrelationCard`(对称矩阵表格 + 红绿色阶)
- 与 P0-2 共享取数骨架与确认门流程,建议同一批次交付

## 6. 数据依赖结论

- P0 三项:**零新数据依赖**,现有 11 张表足够
