## 1. 背景与现状（改造前）

### 1.1 择时缩放块（差异主因）

- 位置:strategy-backtest.service.impl.ts:652 执行阶段 a′ 块，调 `account.rebalanceToTotal(...)`（account.ts:170-219）
- 行为:每交易日执行阶段把总仓位拉回目标暴露（`exposureByDay[i] ?? 100`），带宽 `positionDeviatePct`（缺省 1%）；无择时叠加时目标恒为 100% = **保持满仓维持器**——BIAS20 卖出的现金当日按市值占比整手回补剩余持仓
- 量化:离线全路径重放（2026-10-21，同数据同规则）——引擎 A/B 实测：保持满仓 = 年化 +62.0%/-20.4%；关闭回补 = +55.1%/-20.1%；**回补贡献约 7 个百分点**

### 1.2 涨跌停顺延（自研超集）

- 位置:impl:646（卖出跌停顺延）、:723（买入涨停跳过）、:664-668（择时块 canSell/canBuy）
- 行为:执行价 ≥昨收×1.0999 买入跳过、≤昨收×0.9001 卖出顺延
- 掘金默认撮合不判涨跌停——此项是自研的真实度增强，也是复刻残差来源之一

### 1.3 决策（ADR-0008）

两行为参数化、默认取掘金对齐语义；择时叠加执行器身份保留；参数随确认卡与卡片 config 持久化。

## 2. 语义定义

### 2.1 keepFullyInvested（仓位维持）

- `false`（默认）:卖出规则（BIAS20<0 等）触发的现金**保留**，直到下一调仓日按目标名单再投资——掘金对齐语义
- `true`:每交易日收盘后（决策时点）若 |总仓位 − 全额暴露| > 仓位带宽%，按持仓市值占比整手回补（现金封顶）或减仓（涨跌停/停牌顺延、只动未 T+1 锁定仓）
- 仅在**无择时叠加**时生效；有择时叠加时择时块无条件运行（择时的仓位执行器）
- 全仓清空后不回补（invested=0 不触发加仓腿，与掘金一致）

### 2.2 limitUpDownSkip（涨跌停顺延）

- `false`（默认）:涨跌停价照常成交——掘金对齐语义
- `true`:买入价 ≥昨收×1.0999 跳过（顺延次优）、卖出价 ≤昨收×0.9001 顺延（规则次日仍触发则再判）

## 4. 语义细则与边界

1. 开关仅在**无择时叠加**时生效；有叠加时择时块无条件运行（回补腿也是择时组成部分）——与掘金"仓位维持是策略责任"不冲突（择时是显式配置的策略功能）
2. `keepFullyInvested=false` 且全清仓 → 现金躺到调仓日（invested=0 不触发回补腿，与掘金一致）
3. `limitUpDownSkip=true` 时卖出跌停顺延后，规则次日仍满足则重新触发（与现状顺延语义一致）
4. 每日选股（run_daily_screen）不受影响：单日截面无仓位语义
5. 触发模式（模型 Ⅱ）路由独立引擎，不经过择时块，不受影响
