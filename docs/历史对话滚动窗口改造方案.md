# 历史对话滚动窗口改造方案（ADR-0007 修订 v2）

> 状态：**待拍板**。本方案取代初版「纯环境变量调 refitCap/summaryChars」方案（未实施即废弃，
> 其「压缩次数 = 年龄 = 重要度衰减」定案理由由本方案继承）。定案后补记 ADR-0007 修订段。

## 一、设计输入（原始表述）

> 维护一个记忆最大值：新对话加进来若超出最大值，只保留最近两次历史对话，之前的直接压缩、
> 也作为历史对话的形式存在（相当于往前的第三次历史对话），再把新对话加进去——
> 历史中恒定 4 轮。

## 二、设计目标

1. **未超限：历史原文自然增长**，全部轮次原文照出，不做任何压缩；
2. **超 token 预算才压缩**：新提问加进来若使历史段超过最大 token，开始压缩——保留最近 2 轮原文，
   更早的轮次折叠成摘要轮；此后历史再增长、再触顶时逐轮折叠，维持"摘要轮 + 最近 2 轮原文"形态；
3. **摘要的摘要直接采用**：压缩次数即年龄，重要度自然衰减（v1 定案理由继承）；
4. **参数直觉化**：历史 token 预算 + 保留轮数 + 摘要上限，替代字符阈值/滞后带/重炼天花板整套机制。

## 三、核心机制

### 3.1 轮的定义

一次提问的完整问答 = `conversation.messages` 中相邻的 `[用户气泡, 智能体气泡]` 对（卡片不进上下文，
经 card 通道直达前端；回测重数据在 runs 表按需 `get_backtest_run`）。

### 3.2 窗口推导（每次提问组装时无状态计算，两个状态）

```text
rolls = 把 conversation.messages 切成问答轮数组（最老 → 最新）
historyTokens = 历史段 token 估算（estTokens：中文≈1/字、ASCII≈1/4 字符，与 usage 日志口径一致）

未超限：estTokens(全部历史轮原文) ≤ HISTORY_MAX_TOKENS
  → 全部原文照出，无摘要轮（自然增长）

超限：estTokens(全部历史轮原文) > HISTORY_MAX_TOKENS
  → 从最老轮开始逐轮折叠进摘要轮，直到满足：
     estTokens(摘要 + 剩余原文轮) ≤ HISTORY_MAX_TOKENS，且至少保留最近 2 轮原文
  → 注入序列 = [摘要轮, …保住的原文轮…] + 本轮
```

压缩是稳态：之后历史再增长、再触顶，永远折最老的原文轮（一次一轮，或一轮即可回到预算内则只折一轮）。
折叠触发不需要后台任务——组装时按 estTokens 对比预算即可发现需要折叠的轮。

仅剩 2 轮原文仍超预算的极端情况（单轮超长话术）：如实保留（预算被单轮击穿属有界例外），
不折叠最近 2 轮——尾部保真优先。

### 3.3 摘要轮的形态（与正常对话完全同构：一问一答）

```text
用户：【历史归档】把之前咱们聊的内容整理成要点吧，整理完接着继续。
助手：好的，此前对话要点如下：
      一、需求与结论：……（用户要过什么、定了什么）
      二、已确定的关键参数：……（区间/资金/调仓/持仓/因子方向等）
      三、未决事项：……（聊到一半没落定的事）
```

- **结构与正常轮完全一致**（HumanMessage + AIMessage 对），排进消息流后与真实历史轮不可区分地衔接；
- 摘要正文按"需求结论 / 关键参数 / 未决事项"三段组织——正好对齐摘要器的保留清单；
- 用户行的 `【历史归档】` 前缀是唯一标记，防止模型把这句当成需要执行的新指令；
- 该对是**组装期合成的注入视图**，不落库、不计入 coveredChars 之外的任何存储；
- 备选形态：顶部 SystemMessage（更保守）——做成开关，实测发现模型误引用再切换。

### 3.4 折叠算法（摘要的摘要）

- 沿用 `coveredChars` 指针与无损不变式（原始气泡永不删，指针可回拨重炼）；
- 折叠源恒小：`【此前摘要】旧摘要 + 新被挤出轮的原文`，重写 ≤500 字——**单次折叠 <1k tokens**；
- **只保留 inline 折叠**（组装时顺手做，成本可忽略）；v1 的 background 后台维护路径删除——
  窗口是组装期推导的，没有"提前炼好"的需求，代码显著简化；
- `refitCapChars` 废弃：折叠源恒小，不存在源文本无界问题。

### 3.5 参数（全部走 ConfigService：`.env` 可调，代码内默认值兜底）

| `.env` 键 | 默认值 | 含义 |
|---|---|---|
| `HISTORY_MAX_TOKENS` | 3000 | 历史段 token 预算（estTokens 估算口径），超过即开始压缩 |
| `HISTORY_KEEP_TURNS` | 2 | 压缩时保留的最近原文轮数 |
| `MEMORIES_SUMMARY_CHARS`（沿用，默认 400→500） | 500 | 摘要上限 |
| ~~`MEMORIES_TRIGGER_CHARS` / `MEMORIES_TAIL_CHARS` / `MEMORIES_REFIT_CAP_CHARS`~~ | — | **废弃**（滚动摘要相关；记忆块 maxEntries/budgetChars 不动） |

`configuration.ts` 新增 `history` 段：`{ maxTokens, keepTurns }`，装配处统一 `Number(config.get(...) ?? 默认)`——与既有 `memories.*` 旋钮同款写法，测试构造可改。

## 四、效果

- **未超限零失真**：3000 token 以内的会话历史全部原文，不做任何压缩；
- **超限后有界**：历史段恒 ≤ `HISTORY_MAX_TOKENS`（摘要 + 保留轮原文），极端单轮击穿属显式例外；
- 折叠调用每次 <1k tokens、频率 = 触顶频率——维护成本对共享限流窗口的影响可忽略；
- 老轮次逐次折叠：压缩次数 = 年龄，重要度按设计输入自然衰减；稳定偏好双保险不变
  （保留清单持续携带 + `save_memory` 独立通道永不压缩）。

## 五、风险与对策

| 风险 | 对策 |
|---|---|
| 按轮数不按字符：单轮超长（长需求话术 500+ 字）时 2 轮原文也可能 ~2k 字 | 有界可接受；后续可加"单轮超 800 字先折"兜底，暂不做 |
| 模型把摘要轮当真实对话引用 | `【】`显式标注 + 形态开关（3.3 备选）；evals 观察编造率不升 |
| 长会话摘要质量劣化 | 原始消息无损可重炼；usage 日志 + 人工抽查 + records 指标对账，劣化回滚 |

## 六、验证与回滚

1. **单测**（新增纯函数）：轮切分（0/1/2/3+ 轮边界）、窗口推导、折叠摘要（旧摘要+挤出轮）、
   摘要轮编码、coveredChars 推进；
2. **回归**：现有 ADR-0007 摘要闭环测试改造后全过；server 全量 jest；
3. **真库冒烟**：造一条 >4 轮长会话，检查第 5 问的注入序列形态与摘要要点质量；
4. **观测**：usage 日志确认历史段封顶；records 指标对账（任务完成率/编造率）；
5. **回滚**：代码回退本次提交即恢复（本次为代码改动，非纯旋钮——与 v1 的差异点）。
