## 0. 宗旨：一切皆参数，参数皆可对话确定

**产品最高目标（2026-10-17 定调）：把所有的东西做成参数，让用户通过与智能体的对话来确定这些参数。**

引擎的每个能力都不该是写死的行为，而是一个显式参数；用户不写代码/SQL/JSON，靠对话（澄清引导补全 → 确认门批准 → 授权调优委托）就能定下全部参数并看到结果。这是评估一切新功能的第一问：**这个能力变成了什么参数？**

由宗旨推出的三条硬标准，每条新参数必须全过：

1. **参数面完整（五件套）**：进工具 schema（模型会用）→ 进手写校验 assertXxx（坏参早死）→ 进确认门卡片 params 行（用户看得见才批得对）→ 进回测卡片 config/params 透传（结果可溯源）→ 进策略库 StrategyRunConfig（可保存重跑）。
2. **对话可达**：缺省合理不填也能跑；澄清引导强制携带用户已给值；确认门支持逐组批准/本轮授权/反馈修改三条路。
3. **缺省可复现**：新参数全部缺省时，既有结果逐位不变。

**本批 6 项按宗旨对号**：

| 清单项 | 变成了什么参数 | 对话面 |
|---|---|---|
| §1 大盘条件 | entryFilters 加可选 `indexCode`（缺省 sse）；`mkt_idxd` 引用广播成全池统一值 | 一条普通选股条件，模型/用户同构理解，走既有确认门 |
| §4 eq/bw | op 扩为 `>/</eq/bw`，value 支持 `[lo,hi]` | 条件表达力参数，schema 即文档 |
| §2 排除时间段 | `excludeRanges: [{start,end}]`（≤5 段） | 回测区间参数，确认卡/卡片 params 行展示 |
| §3 不卖条件 | `keepRules[]`（与 sellRules 同构的字段条件组） | 与卖出规则对称的参数组，走确认门 |
| §5 每日选股 | 查询参数：entryFilters+sortFactors+maxPositions+securityIds+date（单日，缺省最近交易日） | 免确认即问即答——对话可达性优先的样板 |
| §6 展示层 | 对数轴/多空视图=卡片交互参数（不进确认门）；IC 衰减 lag 1~5=服务端参数 | 结果查看方式，不拦对话 |

**范围**：本轮只拍第一批 6 项；后续批次同为参数化路线图（§5）；第二、三批语义随数据导入再谈。

## 1. 事实核对（对清单假设的四条修正）

1. **清单 §6"需核对补齐"项，核对结果：两个都没有。** 排名分析 output（`factor-analysis.service.ts:35-54`）只有 lag=1 的 `icSeries` + `icMean/icIR/单调性/段收益`；`longShortSpreadPct` 只是"段1均值−末段均值"一个数（`factor-analysis.service.impl.ts:129-132`），无逐期多空序列、无 IC 衰减、无市值维度。补齐是加服务端数据，不只是前端画图。
2. **"不卖只对抗 sellRules"存在隐藏歧义**：`rank_out`（排名跌出）本身就是 sellRules 六种 kind 之一（`account.ts:257`），且调仓日"不在目标集→卖出"（`strategy-backtest.service.impl.ts:411-420`）是另一条独立路径。字面读"只对抗 sellRules"会把调仓换出也保护进去——必须显式拍板（见 §2.3）。
3. **排除时间段"与果仁口径一致"没有一手依据**：《果仁择时逆向》对该面板零记录，只有清单自己的转述。按清单自写口径拍板，定位是**我们的设计决定**，不是果仁事实。
4. **只读分析工具目前也走确认门**：`CONFIRMABLE`（`langgraph-agent.service.ts:343`）= 回测 + 排名分析 + 相关性。每日选股的确认门取舍需要显式选边（见 §2.4）。

## 2. 决策记录

### 2.1 大盘条件（清单 §1）＋ entryFilters 补 eq/bw（§4）

**现状**：`StrategyFilterRule = {table, field, op: '>'|'<', value}`（`strategy-backtest.service.ts:44-49`），字段名即列名，SQL/ 白名单约束；逐 `(table, field, date)` 取个股截面评估（impl:173-193），缺值视为不满足（契约层:569-570）。指数域读取 `readIndexFieldSeries` 已存在、按 TICKER_SYMBOL 键、目前只服务择时（`mysql-factor-data.service.ts:299-314`，INDEX_TABLE='mkt_idxd' impl:72）。择时条件已有 `bw`（闭区间，`timing.ts:165`）。果仁侧：选股指标确有"大盘指标"类（逆向 §4.1），但指标清单与挂靠指数未逆向；比较符全集为 `gt/lt/eq/bw`（逆向 §4.2）。

**决定**：
- **(a) 混入 entryFilters**：`table='mkt_idxd'` 即触发广播通道（读指数当日值，全池统一值参与过滤）。不设独立顶层参数——一条统一的条件列表就是最好的对话参数面：模型与用户都按"一条选股条件"理解，符合果仁"八大类之一"语义，schema 不加易用错的口子。
- **(b) 指数指定**：每条规则加可选 `indexCode`，枚举沿用 BENCHMARKS `sse|hs300|csi500`（契约层:32-39，与择时同源），缺省 `sse`；要更多指数再扩枚举并登记。
- **(c) 缺值语义分叉**：指数缺值=**弃权**（跳过该条条件）；个股字段缺值维持"不满足"。理由：指数某日缺值是数据缺口不是信号，照抄"不满足"会把整个股票池清空。
- **(d) eq/bw 同批**：op 白名单从 `['>','<']`（契约层:389-391）扩为四种；`bw` 的 value 为 `[lo,hi]` 闭区间二元组（判定语义平移 `timing.ts:165`）；`eq` 精确相等、不做容差。value 类型扩为 `number | [number, number]`。
- **定名**：**大盘条件**（入场筛选的一种，非股票池本身——股票池是 securityIds 静态集合，这是逐日动态开关）。

**落选**：独立 `indexFilters` 顶层参数（校验分支干净，但工具面多一个易用错的口子）；缺省指数套用果仁（未逆向，无据）。

### 2.2 排除时间段（清单 §2）

**现状**：主循环每日三段——执行（impl:364-457）→ 结算（:459-461，无条件）→ 信号（:463-475）。挂起指令链：pendingSells 执行 ：367-377、择时调平 ：381-398、调仓块 ：401-456（:455 重置点）、信号段 ：463-475。结算 `settle` 只按给定价格估值并更新簿记（`account.ts:148-161`），权益估值的停牌回落机制在 `account.ts:97-102`。

**决定**（详见 ADR 0002）：
- **(a) 口径=冻结估值走平**：排除段不喂新价，持仓按期初冻结价估值，净值在排除段走平；收益等指标按全序列计算。"剔除股灾样本"由此才真实成立——排除段的行情涨跌不进收益。
- **(b) 信号停算＋挂起指令丢弃**：进入排除段即丢弃 pendingSells/pendingRebalance；解冻后不补调仓，等下一个自然调仓日。
- **(c) 每期持仓明细**：排除段内无调仓→不产出期行，自然消失，不另标注。
- **(d) 引擎范围**：第一批只做 v3 日频引擎；模型Ⅱ触发引擎同语义列为跟进项（清单 0.5 天估计也只够单引擎）。
- **校验**：`excludeRanges ≤5 段`；排序合并重叠段；倒挂报错；越界裁剪到回测区间。

**落选**：排除段照市价估值只停交易（持仓照跌，剔除名存实亡）；信号照算指令跳过（段内信号无出口，白算；不丢弃挂起指令则解冻首日补执行过期调仓，:455 是现成的坑）；解冻首日补一次到期调仓（与"该段历史当它不存在"相反，周期日历要加补位逻辑）。

### 2.3 不卖条件（清单 §3）

**现状**：卖出三条产生路径——① sellRules 每日盘后判定（impl:464-472，`matchSellRule` `account.ts:223-262`，止盈/止损/回撤止盈/持有满 N 日/字段，rank_out 显式跳过）；② 调仓日换出（不在新目标集→`sellAll`，impl:411-420，理由"调仓卖出/排名跌出"）；③ 择时减仓（每日调平 :381-398＋调仓日目标市值降档 :407-408）。keepRules 入参结构=field 类规则（含本次新增的 eq/bw）。

**决定**（详见 ADR 0003）：保护矩阵=**字段类卖出规则 √、调仓换出 √、择时减仓 ×**（含调仓日降档）。被保住的持仓在调仓日**同权调平**、视同正式成员（TopK=10 保 2 买 8，各 10%）；全保时新股买不进是自然语义，不做特判。清单"两引擎信号阶段先判不卖"维持：v3 与触发引擎同批。

**落选**：只保护①（清单字面窄读——纯排序策略下功能无用，失去主场景）；只保护②（止盈止损被压住是果仁 tooltip 明说的事，砍掉违背原文）；权重冻结不调平（造出"半退出现役"中间态，破坏持仓等权）。

**实现注意**：被保股不在新目标集，需显式纳入调仓日调平目标集（:437-453 现路径只调目标集成员），这是唯一需要特判的点。

### 2.4 每日选股 `run_daily_screen`（清单 §5）

**现状**：信号预计算核心已是纯函数——`applyEntryFilters`（契约层:562-573）、`rankUniverse`（:581-605），编排层内联在回测入口（impl:160-201），未抽壳。工具注册面：spec 常量＋`AGENT_TOOL_SPECS`（tool-specs:312-319）、`TOOL_STAGE`（agent 服务:37-44）、`toolRunners`（:535-542）、`CONFIRMABLE`（:343）。

**决定**：
- **(a) 豁免确认门**：不进 `CONFIRMABLE`，对齐 list_factor_tables/read_factor_data。即查即得的面板体验；零成本零风险（不执行交易），与分析工具进门（重计算、需告知）不同类。
- **(b) 单日**：日期必填，缺省=最近交易日；多日需求用"换个日期再问"覆盖，v1 不做日期列表。
- **(c) 输出带解释**：清单（代码/名称/综合分/关键因子值），不做纯代码列表。
- 参数面：entryFilters＋sortFactors＋maxPositions＋securityIds＋date；入选口径与回测信号完全一致（同一对纯函数）。
- 卡片走新列表型卡（前后端类型联合各加一支）。

## 5. 参数化路线图（后续批次对号入座）

宗旨不变，后续批次都是同一件事：把更多能力变成对话可定的参数。

- **第二批（随数据导入）**：择时衍生指标模板=金叉死叉，落地为 op 追加 `xup`/`xdn`（TIMING_OPS 扩一个枚举值+判定分支）；估值/宽度/两融/ERP=新表入白名单后**自动**成为 entryFilters/timing 可引用字段——参数面随数据生长，引擎零改动，这是"一切皆参数"在数据维度的红利。
- **第三批（外部数据）**：股指对冲模拟=对冲比例/保证金占用/基差处理成为回测参数；实时选股=轮询频率与推送规则参数。
- **待实现池**：模型Ⅲ公式权重、自定义择时公式=表达式参数（公式即参数，配确认门展示）；周/月周期=调仓周期粒度参数；滑点模型=费用参数（与 feeRate 同族）；Parquet 缓存=部署形态参数（非对话参数，不进确认门）。
- **本批预留的参数化接口**：IC 衰减 lag 上限可配；每日选股多日期列表；排除段数上限 5。

### 7.1 逐项落地

- **项1+4（大盘条件+eq/bw）**：`StrategyFilterRule` op 扩 `>/</eq/bw`、value 扩 `[lo,hi]` 二元组、加可选 `indexCode`（缺省 sse，仅 `mkt_idxd` 引用可传）；`applyEntryFilters` 四操作符判定 + 大盘条件哨兵键广播（`INDEX_VALUE_KEY`）+ 缺值弃权；两引擎信号段经同一 `crossSectionSignal` 纯壳读截面（v3 逐调仓日 / 触发引擎逐日），指数序列按 `(table,field,indexCode)` 预载一次（`loadIndexFilterSeries`）。
- **项2（排除时间段）**：`excludeRanges` 归一化=排序→合并重叠→裁剪到回测区间（倒挂/非法/超 5 段报错）；主循环冻结分支=丢弃挂起指令 + `settle(() => undefined)` 冻结估值（复用停牌回落路径，净值走平）+ 信号停算；排除段内调仓日不产出期行（`effectivePeriodStarts`）；触发引擎显式拒绝（不做静默忽略）。
- **项3（不卖条件）**：`keepRules`（结构同 entryFilters 元素，拒指数表字段）；`matchKeepRule` 与 field 类卖出规则同取数通道；v3 三处接线=信号段跳过卖出检查 / 调仓换出保护（`keptCodes`）/ b3 同权调平（`candidates ∪ keptCodes`）；b2 加 `maxPositions` 占坑闸（无 keepRules 时恒不触发，复现不受影响）；触发引擎信号段同语义；`matchSellRule` 未动。
- **项5（每日选股）**：契约层 `runDailyScreen` + `assertDailyScreenInput`（复用 assertFilters/assertSortFactors）；单日截面=回测同款纯函数；date 缺省最近交易日、非交易日自动回落前一交易日（越界才报错）；新工具 `run_daily_screen` 注册（spec/TOOL_STAGE/toolRunners/系统提示），**不进 CONFIRMABLE 免确认**；新 `screen` 列表卡（前后端类型 + ChatPage 分支，含各排序因子值列）。
- **项6（展示层）**：`BacktestChart` 加 `logScale`（净值恒正才生效）+ `PerfChart` 图例区对数轴开关；排名分析 output 加 `icDecay`（持有期 1~5 日平均 IC）、`segmentPeriodReturnsPct`（段×期逐期收益，缺成员 null）、`longShortSeries`（段1−末段复合净值，起点 100）；前端排名卡加"分段累计/多空净值"视图切换（多空用 Sparkline）+ IC 衰减条目。
