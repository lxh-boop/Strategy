## 1. 背景与目标

架构审查（2026-10-16）六个候选项中，首选候选为"**收拢双引擎的资金账户执行原语**"。grilling 过程中另发现两个正确性问题（排序列错位、positionDeviatePct 静默忽略），经确认插入为前置修复。

改造分两批：

- **第 0 刀（正确性修复）**：故意改变回测结果的修复，独立提交，每处变化可归因
- **收拢批次（结构重构）**：以第 0 刀之后的行为为基准做纯移动，要求**逐位复现**

两批不混的原因：修复"故意要变"、收拢"一个数都不能变"，混在同一 diff 里，数字变化无法归因。

## 3. 第 0 刀：正确性修复

### 0a. 排序列按列名对齐

**现状**：取数按名字、用数按下标，中间名字丢失（F1/F2）。

**修法**：调用侧改为按 `表.字段` 名字对齐取截面：

- 两处调用点各自构建 `byName: Map<"表.字段", Map<code, value>>`（模型Ⅰ的 `byRef` impl:200-203 现成，只是 impl:206 丢弃了它）
- `applyEntryFilters` 收到**过滤规则各自名字查出的**截面数组；`rankUniverse` 收到**排序因子各自名字查出的**截面数组。两函数签名不动，只修调用点的对齐
- 触发引擎取数清单从"只取过滤列"扩为**过滤列 ∪ 排序列**（`entryRefs ∪ sortRefs`）
- 同列多规则自然修复：两条规则按名字查到同一份截面

**回归测试**：契约纯函数级新增——两列数值相反的假截面，断言排序按排序列而非过滤列；"同列两条过滤规则"用例。全流程 spec 补"过滤列≠排序列"配置用例（假因子数据源）。真库 E2E 由用户自行验证。

### 0b. 触发建仓尊重 minPositionPct

**现状**：触发买入只查整手与现金（trigger:313-316），F3。

**修法**：镜像模型Ⅰ语义（impl:526）——`equity0 × minPositionPct/100` 为下限，`股数×价格` 低于下限的候选跳过（不建碎仓）。注意 `equity0` 此处已存在（trigger:299）。

**回归测试**：触发模式 spec 补"目标市值低于最小仓位 → 跳过"用例。

### 0c. positionDeviatePct 接上调仓模式

**现状**：择时缩放块阈值硬编码 `equity0 * 0.01`（impl:452），F4。

**修法**：改为 `(p.positionDeviatePct ?? 1) / 100`。**不传 = 1，行为逐位不变**；传了即生效。报错文案（契约 :302"偏离目标总仓位 ±X% 时触发再平衡"）定义的正是这个语义。

**回归测试**：不传走既有用例（天然基线）；新增"传 20 → 缩放阈值变化"用例。

### 第 0 刀的验证标准

三个修复各独立提交。提交后跑真库回测，数字变化**全部可归因**：对比前后持仓明细，每处差异能指出"哪只股票因为哪个修复换掉了"。补齐的测试全绿。

## 4. 收拢批次：结构重构（基准 = 第 0 刀之后的行为）

### 4.1 目标结构一：exposure 序列预计算（收进 timing.ts）

**现状**：择时状态机驱动两引擎各写一份，几乎逐字 27 行，trigger 版丢去重（F5/F8）。

**改造**：timing.ts 新增一个"一次预计算整段 exposure 序列"的函数——输入（overlay、交易日历、截面读取回调），输出 `Map<DayIdx, number>`（逐日目标总仓位%）；逐日"投票→`nextTimingRegime`→`exposureOfRegime`"的折叠过程收拢为一份。截面读取回调由引擎注入（读 factor-data），测试用假读取器。两引擎删除各自的驱动副本，逐日只查序列。去重修复随收拢自然完成。

### 4.2 目标结构二：资金账户 `core/account.ts`

**现状**：资金/持仓逻辑内联两份（buy/sell 闭包、结算、缩放块），权益表达式 4 份（F6）。

**改造**：新建 `core/account.ts`，普通 class，**不做 abstract/impl 分离**（进程内纯域原语、单实现无第二 adapter，契约壳只是仪式）。行为全部来自现有代码的收拢，不新增语义：

```ts
export interface AccountConfig { feeRate: number; lotSize?: number }
export class Account {
  constructor(initialCapital: number, config: AccountConfig)
  cash(): number
  positions(): readonly Position[]            // { code, shares, entryPrice, buyDayIdx }
  equity(priceOf): number                     // 现金 + Σ(持仓×价)，全库唯一一份权益公式
  affordableShares(price): number             // 现金封顶的整手股数
  buy(code, shares, price, day, dayIdx, reason)    // 扣费记账、成交明细一行
  sell(pos, shares, price, day, reason)
  sellAll(pos, price, day, reason)
  rebalanceToTarget(targetPct, ctx)           // 择时缩放/偏离带块：分摊、未锁定仓、停牌涨跌停顺延、整手
}
export function matchSellRule(pos, close, dayIdx, rules): string | undefined   // 纯函数，六种判定同居
```

- 买入 sizing（目标市值、minMv 下限判断）留在引擎——那是策略语义；Account 只回答"给价能买几手"与"按给定股数成交记账"
- Account 不发进度事件、不知道择时概念（exposure 是 rebalanceToTarget 的入参）
- rank_out 判定随 matchSellRule 进入共享原语，触发模式照旧在入参校验层拒绝 field/rank_out（F7 维持）

### 4.3 切换顺序（关键：分步、逐位复现）

**现状**：两引擎独立 impl；模型Ⅰ有全流程用例网。

1. **先切模型Ⅰ**：主循环改为 Account + exposure 序列调用。跑全流程 spec，要求与第 0 刀之后的结果**逐位一致**（trades/curve/dates/config 一个数不差）——"不变"即搬家没搬坏的证明
2. **再切模型Ⅱ**：同标准逐位复现（此时模型Ⅱ的行为变化已全部发生在第 0 刀，收拢本身零变化）
3. 每步独立提交；旧的两份 buy/sell 闭包、缩放块、结算、择时驱动副本在对应引擎切换的同一提交里删除（**替换，不是叠加**——不留新旧两条路径）

### 4.4 assertWhitelist 归口

**现状**：两引擎各一份逐字副本（19 行），真正的字典访问单点在 factor-schema.ts。

**改造**：factor-schema.ts 导出 `assertWhitelist(refs)`，两引擎删除副本改调用。mysql 取数层自己的 assertTable/assertField 不动（取数层独立防御）。`mkt_idxd` 表名常量随本次归口（impl:73 / trigger:127 两处字面量收拢；mysql:37 的常量属取数层不动）。

## 5. 不做 / 不变项

- rank_out 不补进触发模式：排名在该模式只是排队序而非组合身份，每日全域排名破坏懒装载成本模型（已拍板，非缺口）
- 确认门架构不动（ADR-0001 既定）
- Account 不做 abstract/impl 分离、不建 NestJS service 壳
- 文本到数字的映射不进引擎（既有红线）；前端不动

## 8. 实施记录（2026-10-16）

**全部落地**：第 0 刀三项修复 + 收拢四步，与 §3/§4 方案一致。

**与方案的差异（1 处）**：F4 比诊断更深一层——`positionDeviatePct` 不止被引擎忽略，在**契约归一化层就被丢弃**（原 :296-309 只有触发模式分支对其赋值，调仓模式传入的值在归一化后即丢失）。0c 因此额外补了归一化 else 分支：调仓模式可选读取并校验（0~100 的百分比数值），再由择时缩放块以 `?? 1` 消费。

**落地物**：

- 新增 `core/account.ts`：`Account` 类（buy/sell/sellAll/settle/equity/affordableShares/rebalanceToTotal/护栏 tradeLimit）+ `matchSellRule` 共享纯函数 + Position/Quote/SellFieldData 共享类型
- `timing.ts` 新增 `precomputeExposureSeries`（序列读取经注入回调），两引擎删除各自的 27 行状态机驱动（含 trigger 侧丢去重的 `collectTimingRefsOf`，已换 `collectTimingRefs`）
- `factor-schema.ts` 新增导出 `assertWhitelist`，两引擎私有副本删除
- 触发引擎买入 sizing 留在引擎（targetMv/minMv 判断），记账与封顶走 `account.affordableShares`

**验证结果**：

- `tsc --noEmit` 干净
- jest 全量（`--runInBand`）：17 suites / **146 用例全绿**（1 个 manual 触库 spec 按设计跳过）
- **逐位复现成立**：模型Ⅰ切换后 29 用例零改动全过；模型Ⅱ切换后 36 用例零改动全过（含第 0 刀新回归用例）
- 净变化：+309/−444 行（不含新增 account.ts 约 250 行）——两引擎主循环显著收缩
