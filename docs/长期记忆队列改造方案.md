# 长期记忆队列改造方案（ADR-0013）

> 状态：**已拍板**（grill 定稿 2026-10-29），待实施。取代初版「复现刷新 + ★ 显式标记」方案（未实施即废弃）。

## 一、设计输入（定案记录）

1. **长期记忆仿照短期记忆（历史滚动窗口）的机制**：追加制、不做重复判断、容量超限后压缩队头；
2. **载体确定**：一个用户一个 md 文件；
3. **频次即存活**：经常提起的记忆以新条目活在队尾，不再提起的随队头折叠慢慢淡化——
   「压缩次数=年龄」惩罚的是"老且不再出现"，不是"老"；
4. **语义重复可接受**：同一偏好多次追加就是多条，队头折叠时摘要器自然合并——**折叠顺便完成去重**；
5. **显式标记层（★/pinned）取消**：重要 = 用户会再提 → 频次自动保活，单一机制胜过两层特例。

## 二、机制

### 2.1 队列与注入

```text
memories/<userId>/memory.md  （单文件追加队列）
├── frontmatter：summary（折叠摘要，可空）+ foldedCount（已折叠条目数）+ updated
└── 条目块列表（追加序）：
    ## [2026-10-29 09:00] 只用动量因子
    内容一到两句……
    ## [2026-10-29 12:30] 手续费习惯
    ……
```

注入 = 【用户长期记忆】块 = `摘要段（若有，置于头部）+ 未折叠条目（按追加序）`。
条目渲染带日期；不再要求 slug 唯一、不再有 [slug] 引用体系。

### 2.2 容量与折叠

- 计量：`estTokens`（中文≈1/字、ASCII≈1/4，与历史窗口/usage 日志同口径）作用于整个记忆区；
- 触发：注入组装时发现 `estTokens(记忆区) > MEMORY_QUEUE_MAX_TOKENS(2000)` → **inline 折叠**：
  把队头若干条并入 summary（LLM 重写 ≤ `MEMORY_SUMMARY_CHARS`(500) 字，融合旧摘要+队头条目），
  重写 memory.md（新 summary + 剩余条目），`foldedCount` 推进；
- 折叠源恒小（旧摘要+几条队头），单次 <1k tokens；无后台任务，与历史窗口同款"组装时顺手做"；
- 例外：全部条目合起来才超预算（无队头可折的极端）→ 如实全量注入。

### 2.3 工具语义（save_memory 重写）

| 旧 | 新 |
|---|---|
| op=add（slug 唯一，撞车报错） | **op=add = 追加**（不判重；新偏好、重申、修正统一走它） |
| op=update（slug 覆盖） | 废弃——修正 = 追加修正版，旧的留给折叠吞 |
| op=delete（按 slug 删） | **op=delete = 忘掉**：按标题/内容关键词匹配，物理删除**未折叠**匹配条目；相关内容已折叠进摘要的，追加一条「已作废：XX」条目（注入可见，下次折叠消化） |

slug 字段退役（不再有稳定标识与引用体系）；`title` 保留作匹配锚点。留痕规则不变：任何增删，
回复里必须告知用户动了什么。

### 2.4 迁移

现有 `<slug>.md` 条目（个位数）一次性导入队尾（按 updated 序），旧格式文件清除；无 tombstone。

## 三、参数

| `.env` 键 | 默认 | 含义 |
|---|---|---|
| `MEMORY_QUEUE_MAX_TOKENS` | 2000 | 记忆区 token 预算（estTokens 口径），超过即折叠队头 |
| `MEMORY_SUMMARY_CHARS` | 500 | 记忆摘要上限（沿用既有旋钮，默认 400→500） |

`selectWithinBudget`（30 条/800 字预算截断）与 `MEMORY_MAX_ENTRIES`/`MEMORY_BUDGET_CHARS` 废弃——
容量由队列预算统一约束。

## 四、风险与对策

| 风险 | 对策 |
|---|---|
| 二次浓缩失真（折叠的摘要再折叠） | 记忆本体即对话的二手浓缩，二次浓缩可接受（拍板）；summary ≤500 字封顶 |
| 追加制让队列被碎碎念灌满 | 容量预算+队头折叠即自动清理；重要内容用户会复提 |
| 「忘掉」匹配不准（关键词撞车） | 匹配命中多条时回执列出待确认，命中 0 条报错引导；留痕可见 |
| 修正版与旧版并存期模型困惑 | 注入按时间序、新在后；system 规则注明"以最新为准"（与长期记忆块前导语一致） |

## 五、验证

1. 单测：队列读写/追加/折叠（预算触发、foldedCount 推进）/忘掉（未折叠删、已折叠作废条目）/
   迁移导入/注入预算；文件损坏容错沿用；
2. 回归：save_memory 闭环测试改造后全过；server 全量 jest；
3. 真机冒烟：记住→复提（追加）→灌满（折叠）→忘掉（删+作废）全链路；
4. 观测：usage 日志记忆区封顶（≤2000 tokens 附近）。
