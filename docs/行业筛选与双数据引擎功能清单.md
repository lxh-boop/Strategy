# 行业筛选与双数据引擎 功能清单

> 更新:2026-10-20 · 状态:v2 链路复用修订（见方案 v2 头部变更列表），待实施
> v2 要点:① 不建独立名录工具——行业字典接入既有表目录注入 + read_factor_data 路由链；② industries 数量不设上限；③ 每日选股对称支持；④ 引擎 B 裁剪为最小集，注册保险/私密目录挪后续批次
> 背景:通联库内无行业成分表（`md_industry` 拟名未同步），行业筛选的数据源改用 Tushare 申万成分（已下载至 `factor-agent-server/SQL/industry/`）；借此机会建**双数据引擎**，为用户私密数据（CSV 自助放置）留出通道。
> 依据:ADR-0004《双数据引擎：字典即路由与来源无感》、GLOSSARY.md「数据引擎」词条簇、SQL/industry/ 字典六件套。

## 功能条目

### 1. 行业筛选回测（本期主功能）

**用户能做的事（对话示例）**:"回测食品饮料+电力设备，2023-09 到 2026-09，每月调仓，持仓 5 只"——回测股票池限定为所选申万一级行业的并集。

**语义**:行业筛选 = 股票池收窄，与现有"全市场"平级的一种池子口径；筛选、排序、卖出规则等其他参数完全不变。

**口径**:**时点行业归属（PIT）**一步到位——每次调仓日按"当日谁属于该行业"重建候选池（纳入日期 ≤ 调仓日 ≤ 调出日期，调出日期为空视为仍在册）；期内调出行业的股票在下次调仓自然被剔除。数据源 = `sw_member_current.csv`（在册 5918 行）+ `sw_member_historical.csv`（已调出 2006 行）合并。

**实现要点**:引擎 B（DuckDB）导入两个成分 CSV 建 PIT 查询；`run_strategy_backtest` 加公开参数 `industries`（申万一级行业名，**数量不设上限**，31 个全选合法）；解析出的证券集合转成 `securityIds` 走现成通道（strategy-backtest.service.impl.ts:182/407），回测内核零改动。GLM 的行业知识（有哪些行业、各多少只、成分明细）经既有链路获得：表目录注入 + read_factor_data 自查 sw_classify/sw_member（v2 起行业字典接入该链路），**不建独立名录工具**。

**量**:0.5 天（依赖引擎 B 就位）。

### 2. 双数据引擎并存

**说明**:引擎 A = 公共 MySQL 库（herms_data，因子截面/行情/交易日历，现状不动）；引擎 B = 本地 DuckDB 文件库（行业/板块，以及将来用户放的任何私密数据）。两引擎同时注册、各自服务自己字典里的表；回测取数时两引擎的请求并行发出互不拖累。

**实现要点**:core 抽 DataEngine 契约，`MysqlFactorDataService` 归位引擎 A；新增引擎 B（duckdb npm 包，约 40MB 原生依赖）。

**量**:0.5 天。

### 3. 用户自助放置私密数据（CSV 放入即用）

**说明**:用户把任意 CSV 放进私密数据目录、配一份字段字典 md，即完成注册——引擎 B 自动可查，无需改代码、无需导入公共库。

**实现要点**:数据目录 `factor-agent-server/data/private/`（gitignore）；字典目录 `SQL/private/`（md 入库）；支持自动物化 parquet 提速（可选）。

**量**:0.5 天（含目录扫描与注册流程）。

### 4. 注册保险（冲突拦截）

**说明**:用户"只是大概知道公共库的内容"，可能放进与公共表撞车的数据。注册时自动检查：**表名或唯一键与既有表冲突 → 硬拦**（报冲突清单，改名后重放）；仅业务域重叠（表名不同）→ 放行 + 日志软告。

**实现要点**:注册流程内置检查器；检查范围 = 公开字典 + 私有字典已注册集合。

**量**:0.25 天。

### 5. 数据字典分离与来源无感

**说明**:公开字典（`SQL/tables.md`）与私密字典（`SQL/private/`）物理分离；对 GLM 呈现**合并后的统一数据目录**，不携带任何来源标记——模型可点名任意数据（"用申万的行业"、"用我的 XX 因子"），但分不清哪张来自用户文件、哪张来自公共库（**来源无感**，GLOSSARY 有词条）。

**实现要点**:prompt 组装处把两套字典的表目录合并注入；卡片 params、确认门文案等展示层一律不出现"私密/引擎/来源"字样。

**量**:0.25 天。

### 6. 展示层配套（合并一批）

- 确认门新增「行业筛选」行：列出所选行业 + 解析后候选股票数（用户可核对池子大小再确认）
- 回测卡片 params 带「行业筛选」一项（引擎产出透传，口径与对话卡片一致）
- 行业参数给模型的名录：申万一级 31 个行业名（来自 sw2021_classify），写入工具 schema 描述

**量**:0.25 天。

## 验收口径

1. PIT 抽查：600519 任意历史日期 ∈ 食品饮料；600681 在 2017-05-25 后不属于建筑装饰
2. 冲突保险：放入与公开表同名的 CSV → 注册被拒并列出冲突清单
3. 来源无感：注入 prompt 的目录与卡片、确认门全文检索不到"私密/引擎/Tushake/来源"等标记词
4. 行业筛选 E2E：对话回测 → 确认门出现行业行与候选数 → 回测期内每次调仓的候选全部属于所选行业的当日归属
5. 既有测试零回归（当前 182 通过）
