# 归因分析与因子迭代方案（好/坏经验驱动的策略迭代循环）

日期：2026-10-24 ｜ 状态：grill 定案，实施未开工（等开工令） ｜ 关联：ADR-0010（卡片会话级持久化，本方案复用其编号与落库模式）、ADR-0011（字段化筛选，键型适配已收口）

## 1. 背景与定位

目标用户（果仁网类条件选股用户）的深层诉求不是一张贡献分解报表，而是**从好/坏经验中持续改进策略**：跑完回测后，"好的策略/时期"里藏着值得提炼的选股规律，"坏的策略/时期"里藏着该做风控的信号——把这些经验变成因子，加回策略验证，迭代到确认改善为止。这正是传统策略迭代的循环。

**本方案=两层**：

1. **归因底座**（贡献分解）：个股贡献、卖出规则贡献、期间对比——它不再是主交付，而是**好/坏判定的量化依据**；
2. **因子迭代循环**（主交付）：好/坏段挖掘 → 统计+LLM 假设 → 候选因子逐个加回原策略验证 → 三象限采纳判定 → 样本外复核 → 版本链沉淀，循环迭代直到确认改善。

数据地基零新取数：trades 带 reason 标签、periodHoldings 已算到每期每票、个股因子值可按票按区间读取（equ_factor_obos 等库内因子表）、date 类型与 TICKER_SYMBOL 键型适配已收口（ADR-0010/0011 配套）。

## 3. 总体闭环

```
原策略回测（样本内 70% 区间）
   ↓
归因底座：贡献分解（个股/规则/期间）+ 双粒度好/坏判定
   ↓
挖掘：好/坏组因子值分布对比（效应量排序）→ GLM 机制假设与命名
   ↓
候选因子假设包（字段/方向/落点 sortFactors|entryFilters/样本统计）
   ↓
逐个贪心验证：加回当前基线重跑样本内区间 → 三象限判定
   ├─ 采纳 → 基线更新 → 继续下一候选
   └─ 拒绝 → 失败经验记录 → 下一候选
   ↓
后 30% 样本外复核（整体采纳组一次性复核）
   ├─ 达标 → 生成新版本策略 + 迭代报告
   └─ 不达标 → 整批标记过拟合嫌疑，仅存档
   ↓
用户复盘 → 可发起新一轮迭代（基线=新版本策略）
```

## 4. 归因底座（贡献分解）

### 4.1 个股贡献（全口径）

```
每只票：已实现盈亏 = Σ(FIFO 卖出配对 × (卖价 − 配对买入成本)) − 分摊费用
        期末浮动   = 期末持有股数 × (期末收盘 − 加权成本)
        归因贡献   = 已实现 + 期末浮动（分两列展示）
        胜率       = 盈利平仓批次 / 全部平仓批次
```

FIFO 配对复用掘金对账已验证的批次算法（.tmp_parity_audit3.js 的 FIFO 实现迁移为正式代码）。

### 4.2 卖出规则贡献

按卖出流水 `reason` 分组（止盈/止损/回撤止盈/持有期满/字段触发/排名跌出/调仓卖出/调仓减持/择时减仓）：笔数、已实现盈亏、平均持有天数。口径按"平仓批次的触发规则"计——同一持仓先后被不同规则卖出分属不同批次。

### 4.3 期间对比

复用 periodHoldings（每期每票 periodReturnPct/weightPct），新增：期内个股贡献 = 权重 × 期间收益，每期输出 top 正/负贡献。

## 5. 好/坏判定与因子假设挖掘

### 5.1 双粒度好/坏判定

- **期级**：每期组合收益 vs 基准同期收益 → 期好/期坏（择时/仓位假设素材）；
- **票级**：期内每票持有段收益 vs 同期全部持仓中位 → 票强/票弱（选股因子假设素材）。

### 5.2 统计对比

对每只票、每个库内因子字段（可筛范围 = 字典登记的因子表字段），取好/坏两组的因子值分布，计算区分度（组间均值差标准化效应量），按 |效应量| 排序输出区分度字段清单。

### 5.3 LLM 机制假设

GLM 输入 = 区分度字段清单（含效应量与两组分布统计）+ 好/坏段持仓与市场状态概要；输出 = 候选因子假设（字段/方向/机制逻辑/假设命名，如"低乖离+低波动防御特征"）——即 factor-generation 的"明确任务/机制假设"输入形态。

## 6. 迭代验证循环

- **单候选验证**：候选加到当前基线（打分候选→sortFactors 追加/调整方向；筛选候选→entryFilters 追加），重跑样本内区间回测，按三象限判定；
- **贪心顺序**：按区分度降序逐个验证；
- **样本外复核**：全部候选采纳后，冻结因子组重跑后 30% 区间，与原策略同期对比（同三象限判定，阈值同上）；
- **回测执行**：复用现有回测引擎与确认门（授权模式免逐组确认）。

## 7. 双入口与交互（ADR-0010 同模式）

- **对话内**：用户"帮我做因子迭代/从这次回测里挖因子" → GLM 调 run_factor_iteration（入参 strategyId 或 card_N + 可配阈值）→ 每轮进度事件汇报 → 产物 = 新版本策略 + 迭代报告卡；
- **策略页**："因子迭代"按钮（同授权模式）→ 同管线；
- **归因卡**：每轮归因结果（好/坏段对比 + 候选假设 + 验证结论）作为卡片区块或独立卡展示。

## 9. 明确不做与边界

- **不做**：因子回归归因（v2，前置=通联风险模型表 dy1d_exposure_sw21+zx20 同步）；行业 Brinson（v1.1）；回测后自动执行归因；执行侧真并行；盘中归因；
- **边界**：挖掘对象限于持仓段与调仓期（不挖掘未持有股票的假设——那是筛选器的事，属因子挖掘管线的另一入口）；样本外复核只做一次（多次复核=变相样本内）。

## 10. 验收标准

1. 对已保存策略发起因子迭代：全流程自动完成，每轮有汇报，产物为新版本策略 + 迭代报告；
2. 三象限判定与阈值一致（构造用例验证：收益降/回撤升的组合必须被拒）；
3. 样本外复核切分点按调仓期对齐；
4. 采纳成功的版本链可追溯（每版的因子差异与各轮指标可查）；
5. 失败候选进失败经验；
6. 全量测试绿 + 真图冒烟。
