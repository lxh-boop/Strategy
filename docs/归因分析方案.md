# 归因分析与因子迭代方案（好/坏经验驱动的策略迭代循环）

日期：2026-10-24 ｜ 状态：grill 定案（含第四轮持久化简化），实施未开工（等开工令） ｜ 关联：ADR-0011（字段化筛选，date/键型适配已收口）

## 1. 背景与定位

目标用户（果仁网类条件选股用户）的深层诉求不是一张贡献分解报表，而是**从好/坏经验中持续改进策略**：跑完回测后，好的策略/时期里藏着值得提炼的选股规律，坏的策略/时期里藏着该做风控的信号——把这些经验变成因子，加回策略验证，迭代到确认改善为止。这正是传统策略迭代的循环。

**本方案 = 两层**：

1. **归因底座**（贡献分解）：个股贡献、卖出规则贡献、期间对比——不再是主交付，而是**好/坏判定的量化依据**；
2. **因子迭代循环**（主交付）：好/坏段挖掘 → 统计+LLM 假设 → 候选因子逐个加回原策略验证 → 三象限采纳判定 → 样本外复核 → 循环迭代直到确认改善。

配套归因区块（回测/迭代报告附带）：贡献分解三层 + **亏损侧专区**（4.4：回撤窗归因/行为四分类/尾部集中度/规则反事实矩阵）——贡献回答"赚在哪亏在哪"，亏损侧回答"哪类决策在重复亏钱"，合成完整归因双视图。

数据地基零新取数：trades 带 reason 标签、periodHoldings 已算到每期每票、个股因子值可按票按区间读取（equ_factor_obos 等库内因子表）、date 类型与 TICKER_SYMBOL 键型适配已收口。

## 3. 总体闭环

```
已保存策略（样本内 70% 区间回测）
   ↓
归因底座：贡献分解（个股/规则/期间）+ 双粒度好/坏判定
   ↓
挖掘：好/坏组因子值分布对比（效应量排序）→ GLM 机制假设与命名
   ↓
候选因子假设包（字段/方向/落点 sortFactors|entryFilters/样本统计）
   ↓
逐个贪心验证：加回当前基线重跑样本内区间 → 三象限判定
   ├─ 采纳 → 基线更新（原地更新策略配置）→ 迭代日志追加条目 → 继续下一候选
   └─ 拒绝 → 失败经验记录 → 日志追加条目 → 下一候选
   ↓
后 30% 样本外复核（整体采纳组一次性复核）
   ├─ 达标 → 迭代完成（策略配置已含全部采纳因子）
   └─ 不达标 → 整批标记过拟合嫌疑，回退本轮采纳（日志留痕）
   ↓
用户复盘 → 发起新一轮迭代
```

未保存策略分支：对话内对未保存回测发起迭代 → 过程与结论只在对话历史（F7 同口径），不入策略日志。

## 4. 归因底座（贡献分解）

### 4.1 个股贡献（全口径）

```
每只票：已实现盈亏 = Σ(FIFO 卖出配对 × (卖价 − 配对买入成本)) − 分摊费用
        期末浮动   = 期末持有股数 × (期末收盘 − 加权成本)
        归因贡献   = 已实现 + 期末浮动（分两列展示）
        胜率       = 盈利平仓批次 / 全部平仓批次
```

FIFO 配对复用掘金对账已验证的批次算法（.tmp_parity_audit3.js 的 FIFO 实现迁移为正式代码）。

### 4.2 卖出规则贡献

按卖出流水 `reason` 分组（止盈/止损/回撤止盈/持有期满/字段触发/排名跌出/调仓卖出/调仓减持/择时减仓）：笔数、已实现盈亏、平均持有天数。口径按"平仓批次的触发规则"计。

### 4.3 期间对比

复用 periodHoldings（每期每票 periodReturnPct/weightPct），新增：期内个股贡献 = 权重 × 期间收益，每期输出 top 正/负贡献。

### 4.4 亏损侧专区（不对称透镜，贯穿前三维度）

贡献分解是"对称的刀"（正负各拆一遍），但亏损与盈利在数学与行为上不对称——亏 50% 需赚 100% 回本，亏损的行为成因也与盈利完全不同。四个专属度量（阈值可配，缺省如下）：

1. **回撤窗口归因**：权益曲线自动切分回撤窗（峰→谷→修复），每窗输出起止日期、深度、持续天数、窗内主要亏损个股（top 3）、窗末修复方式（反弹修复 / 止损离场）；
2. **亏损行为四分类**：每笔亏损平仓归入——买错（入场后 10 日内最大浮盈 ≤2% 且亏损离场）/ 卖晚（平仓浮亏 ≤ 持有期最大浮亏一半，回吐过半仍持有至亏损）/ 卖早（卖出后 5 日内涨幅 ≥5%，机会成本侧不计入已实现亏损）/ 踏空（空仓或仓位 <30% 期间市场上涨段，机会成本侧）；输出四类笔数与金额占比；
3. **尾部与集中度**：最差 5 笔平仓占总已实现亏损比、最大单票亏损、最大连亏批次与幅度、盈亏比（平均盈利/平均亏损）；
4. **反事实规则复盘**：对每条卖出规则做"剔除重跑"对比（掘金 rank_out 事故定案即此法，方法论已验证），输出规则开关矩阵——每规则保留/剔除两行指标（年化/回撤/交易笔数）。反事实复盘计算量 = 卖出规则数 × 样本内回测（规则 ≤5 条可控），其余为流水纯聚合。

## 5. 好/坏判定与因子假设挖掘

### 5.1 双粒度好/坏判定

- **期级**：每期组合收益 vs 基准同期收益 → 期好/期坏（择时/仓位假设素材）；
- **票级**：期内每票持有段收益 vs 同期全部持仓中位 → 票强/票弱（选股因子假设素材）。

### 5.2 统计对比

对每只票、每个库内因子字段（可筛范围 = 字典登记的因子表字段），取好/坏两组的因子值分布，计算区分度（组间均值差标准化效应量），按 |效应量| 排序输出区分度字段清单。

### 5.3 LLM 机制假设

GLM 输入 = 区分度字段清单（含效应量与两组分布统计）+ 好/坏段持仓与市场状态概要 + 亏损侧专区摘要（4.4，回撤窗/四分类占比/尾部集中度）；输出 = 候选因子假设（字段/方向/机制逻辑/假设命名，如"低乖离+低波动防御特征"）——即 factor-generation 的"明确任务/机制假设"输入形态。

## 6. 迭代验证循环

- **单候选验证**：候选加到当前基线（打分候选→sortFactors；筛选候选→entryFilters），重跑样本内区间回测，三象限判定；
- **贪心顺序**：按区分度降序逐个验证；
- **样本外复核**：全部候选采纳后，冻结因子组重跑后 30% 区间，同三象限判定（阈值一致）；
- **回测执行**：复用现有回测引擎与确认门（授权模式免逐组确认）。

## 7. 迭代日志持久化（简化形态）

### 7.1 存储

strategies 表新增 `iterations` JSON 列（与 params/periodHoldings/trades 同模式）：

```json
[
  {
    "time": "2026-10-24",
    "factor": "低波动（HSIGMA 升序，样本内回撤 -10.1%→-8.2%）",
    "purpose": "假设：低波动防御特征在下行段保护组合",
    "result": "年化 +17.8%→+19.2%，回撤 -10.1%→-8.2%",
    "verdict": "成功（回撤改善型）",
    "summary": "GLM 一句话总结：低波动因子在下行段显著降低回撤且收益非劣，采纳"
  }
]
```

- 采纳与被拒的候选都记录（verdict 区分"采纳/拒绝+原因"）；
- 同日重复验证同因子 → 覆盖当日条目；跨日 → 追加（演进可回看）；
- **删除策略即删除日志**（整行删除，天然级联）。

### 7.2 LLM 总结

每条目的 `summary` 由 GLM 依据前后指标生成一句话归因总结（复用"回执摘要写文案"的约束：只引用指标数字）。

### 7.3 展示

策略详情页新增"因子迭代日志"入口（与历史持仓/历史交易同模式滑入层），按时间倒序展示条目。

## 9. 明确不做与边界

- **不做**：因子回归归因（v2，前置=通联风险模型表 dy1d_exposure_sw21+zx20 同步）；行业 Brinson（v1.1）；回测后自动执行归因；执行侧真并行；盘中归因；归因聚合报表持久化；版本链与策略快照（日志即还原指南）；
- **边界**：挖掘对象限于持仓段与调仓期（未持有股票的假设属因子挖掘管线另一入口）；样本外复核只做一次（多次复核=变相样本内）；
- **未保存策略**：迭代过程只在对话历史，不入策略日志；如需入日志先保存策略。

## 10. 验收标准

1. 对已保存策略发起因子迭代：全流程自动完成，每轮有汇报；日志条目五要素齐全；
2. 三象限判定与阈值一致（构造用例验证：收益降/回撤升的组合必须被拒）；
3. 样本外复核切分点按调仓期对齐；
4. 采纳后策略配置原地更新，日志与配置可交叉核对；
5. 失败候选进失败经验（verdict=拒绝+原因）；
6. 未保存策略发起迭代 → 提示先保存；删除策略 → 日志级联清除；
7. 全量测试绿 + 真图冒烟。
