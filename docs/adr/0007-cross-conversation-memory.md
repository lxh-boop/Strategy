# ADR-0007：跨对话长期记忆与会话内上下文压缩

日期：2026-10-21　状态：已采纳（grill 三轮收口，用户逐项拍板；方案详见 `docs/跨对话记忆与上下文压缩方案.md`）

## 背景

智能体记忆边界三层硬截断、零压缩机制：轮内完整；轮间只有 `slice(-6)` 的 3 轮文字（`langgraph-agent.service.ts:1064`），卡片与工具回执从不进 prompt；跨对话为零，换会话即全失忆。调优对话超 3 轮即丢上下文，偏好与结论每次从零重述。压缩机制（写入压缩/库内合并/会话内摘要）代码里均不存在。

## 决策

1. **长期记忆 = 条目式，本地 md 文件，零数据库**（用户明确否决 MySQL 落库）：一条记忆一个 md 文件（slug + frontmatter），`memories/<userId>/` 一人一目录；每轮全量注入 system prompt，条数/字数预算封顶。内容只收用户偏好与策略研究结论，不存全量会话摘要。
2. **写入 = `save_memory` 三操作工具（新增/更新/删除），不过确认门**：库内压缩在写入现场由模型完成（模型每轮见全量条目，改偏好即覆盖，无后台合并任务）。防线是**记忆留痕**——写入必须同时在进度事件与回复气泡可见，以可见性替代确认门；管理走对话指令 + 手改文件双通道，v1 无 UI。
3. **会话内压缩 = 长度触发的滚动摘要**（参照 DeepSeek Harness compaction）：气泡总字符数（非条数）超阈值（缺省 2000 字）时，把尾部（800 字）之外的全部原文重炼成**一条**摘要消息（SystemMessage，带前缀）注入；后台异步执行、prepare 时懒兜底。**无损不变式**：任何历史消息要么在摘要里、要么原文注入；**原始记录永不覆盖**——MySQL messages 即只追加日志，摘要随时可从原文重炼（无"摘要的摘要"失真），md 摘要文件只是缓存。
4. **记忆与数据上下文划界**：长期记忆属用户上下文，任何会话（含闲聊）都注入；「数据会话」的闲聊零注入只约束数据上下文（表目录、轮次预算），两者不冲突。

## 后果

- 新增 `MemoryStoreService` 契约 + md 文件实现（不做 memory 兜底双实现，文件天生本地可用，测试注 tmp 目录）；`Conversation`/`reply` 签名需贯通 userId。
- `prepareMessages` 主链路重写（`slice(-6)` 退役）：短会话全量原文注入，保真度优于现状；长会话注入量稳定在摘要 ≤400 字 + 近段原文 800~2000 字。
- 摘要有损（用户知情确认）；记忆写入无门，事故兜底靠留痕 + 对话删除 + 手改文件。
- 超阈值会话每轮多一次后台 flash 级摘要调用；七 个数值全部为配置旋钮（`MEMORIES_DIR`、触发/尾部/摘要字数、注入预算、重炼上限）。

## 修订（2026-10-29，prompt 分支）：会话内压缩改为 token 预算触发的滚动窗口

原第 3 条的「字符阈值（2000）+ 后台全量重炼（30k 上限）」机制废弃，改为：

- **触发**：历史段 token 估算（`estTokens`：中文≈1/字、ASCII≈1/4，与 usage 日志同口径）超过
  `HISTORY_MAX_TOKENS`（缺省 3000）才开始压缩；未超限全部原文照出，零失真。
- **压缩形态**：保留最近 `HISTORY_KEEP_TURNS`（缺省 2）**轮**原文，更早轮次增量折叠成**摘要轮**——
  以与正常对话同构的一问一答（用户：【历史归档】… / 助手：三段要点）注入消息流，不再是顶层 SystemMessage。
- **折叠 = 摘要的摘要**（「旧摘要 + 新被挤出轮」增量重写 ≤500 字）：压缩次数即年龄、重要度随年龄衰减，
  不再追求"全量重炼防失真"——大压缩比下全量重炼同样失真，且每次 15-20k tokens 的维护调用打在
  共享限流窗口上；增量折叠单次 <1k tokens。稳定偏好由 `save_memory` 独立通道（永不压缩）双保险。
- **实现简化**：只保留 inline 折叠（组装时推导），background 维护路径删除；
  `MEMORY_TRIGGER_CHARS`/`MEMORY_TAIL_CHARS`/`MEMORY_REFIT_CAP_CHARS` 三旋钮废弃。
- 无损不变式不变：原始 messages 永不覆盖，摘要随时可从原文重炼；结构化数据仍走 `get_backtest_run`。

方案全文见 `docs/历史对话滚动窗口改造方案.md`。
