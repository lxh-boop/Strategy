# 权重与仓位函数化：GLM 传函数名，注册表求值

Status: accepted（2026-10-17 定案，待实施）

因子权重（现状 `sortFactors[].weight` 静态数字列）与持仓仓位（现状等权）统一函数化：后端内置**函数注册表**（代码维护），GLM 只传 `{name, params}`——函数名 + 策略旋钮参数——引擎在每次调仓时执行注册表中的函数。本决策正式修订 v3 设计原则"引擎只收数字参数"：引擎现在接受"注册表函数引用"，但模型输出依然不是代码，注入面（eval/沙箱/表达式审计）为零。关键约束：**参数只放策略旋钮，一切数据类输入（因子截面、IC、名次、剩余资金）由引擎上下文供给**——因子值唯一事实是数据库，先缓存后取数（现有 readFactorSection 路径，一次取数排序与定权两用）；GLM 在生成参数时不知道运行期的股票与现金，故参数只能是份额/规则，金额是函数在每期的输出。仓位函数返回**金额字典**，独立校验器（整手/现金/上限）逐条修正并出违规清单。等权内化为 `constant` 函数（因子权重版=静态 weight 列，仓位版=按名次比例×当期剩余现金），旧 config 的静态 weight 列由兼容层翻译，复现不变。缺值语义沿用现状（个股缺值该因子不计分并重归一、全缺出局、整列缺失因子跳过）。

## Considered Options

- **GLM 直传表达式 DSL（mathjs 求值）**：否决——模型输出即代码面，安全审计与确认门可读性都差；函数名+参数把语义压回注册表，表达力由"加注册函数"承载。
- **零参预置模式枚举**：否决（用户拍板需要参数）——常数比例等函数天然需要参数，参数经 schema 校验、只放策略旋钮。
- **权重函数向量表达式/矩阵运算**：否决——求值粒度定为引擎喂上下文、函数输出标量或字典，求值器不引入数组语义。
- **仓位函数返回份额**：否决（用户拍板金额）——金额契约要求独立校验器，把整手/现金/上限检查前置显性化。
- **静态 weight 列与 weightFn 双轨并存**：否决——新接口统一函数形式，静态列只在旧 config 兼容层翻译。
- **缺值回退等权 + 告警**：否决（用户拍板沿用现状）——静默降级语义自洽，行为零变化。
