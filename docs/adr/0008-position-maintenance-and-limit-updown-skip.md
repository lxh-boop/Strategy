# 仓位维持与涨跌停顺延：掘金对齐为默认语义

Status: accepted（2026-10-22 grill 定案，已在工作区实施待验收）

掘金交叉验证（2026-10-21）暴露引擎默认语义与主流平台的 executing 层分歧：**择时缩放块**（每交易日收盘后把总仓位维持在全额暴露，BIAS20 卖出的现金当日按市值占比回补剩余持仓）引擎同配置 A/B 实测（2026-10-22）：开启 = 年化 +62.0%/-20.4%，关闭 = +55.1%/-20.1%，贡献约 7 个百分点（2025 有色上涨段；早期"36pp"系重放与引擎的语义差异被误记为回补贡献，已勘误）；**涨跌停顺延**（执行价触及涨停不追、触及跌停不卖）则是自研超出掘金默认撮合的准确性增强。决定：两行为**全部参数化，默认值取掘金对齐语义**——`keepFullyInvested`（缺省 false）与 `limitUpDownSkip`（缺省 false）；默认关=跨平台复刻对照时默认口径一致，开启则为自研的真实度/收益增强项。择时叠加不受开关影响：有择时叠加时择时块无条件运行（它是择时的仓位执行器，开关仅作用于"无叠加时的隐性满仓维持"）。依据：当前无存量用户与历史策略，默认翻转无迁移负担；打磨期第一目标是与主流平台结果可互证。

## Considered Options

- **保持满仓维持为默认、对照时手动改参**：否决（用户拍板）——"和主流保持一致"是打磨期的验收标准，默认口径必须就是对照口径；靠记忆传参的对照不可复现。
- **彻底删除择时缩放块**：否决——该块同时是择时叠加的仓位执行器，删除使择时叠加失效；收敛为参数门控（无叠加+false 才跳过）。
- **涨跌停顺延保持无条件启用**：否决（用户拍板全部参数化）——它正确但与掘金默认撮合不一致，是复刻残差来源之一；参数化后既可关闭对照、也可开启增强真实度，两全。
- **positionDeviatePct 默认值改 100 代替新参数**：否决——复用带宽参数语义过载（触发模式必传 5~50，与调仓模式语义冲突），且"仓位维持"与"缩放带宽"是两个意图。

## 后续追加（2026-10-22，掘金对照第二阶段）

**executionTiming=2（信号日当日收盘成交·尾盘单）**：掘金对照实验进一步发现，掘金项目的撮合时点为"决策日 15:30 下单 → 当日收盘价成交"（零滞后，导出数据实证：0102 15:30 下单、当日 EOD 已建仓 69.7 万），而自研 0/1 模式均为 T+1 执行（隔一夜）。按用户拍板新增模式 2：T 收盘出信号、**T 收盘价成交**（同 bar 执行）。真实场景 = 尾盘单（14:55 用即时价算信号、收盘集合竞价成交），轻微乐观（信号价格与成交价格为同一根 bar），是业界可接受的回测口径。默认值仍取掘金对齐（用户显式传 2 时启用），不下沉为默认。
- 实现：日循环支持 mode 2 的"当日信号 → 当日收盘执行"同日相位（信号阶段前移 + 执行块门控扩展）
- 验证：首期建仓落在决策日当日收盘（trade date = 20240102）；BIAS20 卖出在信号日当日收盘成交（专项测试 6 例全过）
