# ADR-0006：股票池筛选独立工具与规格句柄

日期：2026-10-21　状态：已采纳（grill 收口，用户逐项拍板）

## 背景

股票池限定散落在两个引擎参数（`industries` 行业名、`securityIds` 显式清单），没有指数成分来源；显式清单必然进 prompt（手拼长清单是编造事故温床）。行业筛选（ADR-0004 的 industries 参数）是引擎内逐调仓日 PIT 解析，清单从未物化——该模式无法泛化到指数成分与用户自定义筛选。

## 决策

1. **股票池筛选独立为 GLM 工具 `screen_stock_pool`**（免确认、只读）：入参为两层筛选规格（组内并集、组间交集；来源 kind = industry / index / list）。
2. **规格句柄**：工具产物存 MySQL `alphasage_user.pool_refs`（规格 + 摘要 + 筛选时点成员数），回执只给 GLM `poolId + 摘要 + 成员数`；回测/每日选股以 `poolId` 引用，编排层解析回规格。成员清单全程不进 prompt。
3. **动态 PIT 跟随**：句柄存**规格**不存清单，引擎逐调仓日按时点解析成员（行业成分、指数成分期内调样自动跟随）。查证依据：聚宽 `get_index_stocks` 缺省回测当前日、果仁以消除存活偏差为卖点、静态快照引入幸存者偏差虚高收益（SSRN S&P 500 研究）。"定了不会变"落实为筛选**定义**不变。
4. **回测引擎入参收敛**：删 `industries` 参数（行业降级为池规格的一种来源），保留 `securityIds`（显式清单直传）；触发模式（模型Ⅱ）不支持 pool → 400。
5. **摘要即参数**：引擎入参 `pool` 携带展示摘要，三处"股票池"行内联三元直读，不新增查询链路（"回测卡一定正确"与"不加东西"两条规则的交集）。

## 后果

- 新增一处工具间产物存储（pool_refs 表 + store 三实现）；句柄随会话有效，保存策略以规格快照随 config 落库、重跑自包含。
- 指数成分数据以月度快照落 DuckDB（idx_member），PIT 查询取 `≤ asOf` 最近快照；数据源缺失 fail fast。
- 476b220 的 industries 引擎内解析机制保留但入口改造（industries 字段 → pool.groups），dayPool 逐日解析逻辑是本设计的执行核心而非退役对象。
