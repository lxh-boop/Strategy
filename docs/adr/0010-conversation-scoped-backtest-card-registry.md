# ADR-0010：回测卡片会话级持久编号与完成即入册

Status: accepted（2026-10-23 grill 定案；实施未开工，规格见 docs/回测卡片会话级编号与独立存储方案.md）

## Context

卡片编号是回合内临时指针：tools 节点对任何产卡工具顺序发号（card_N = 本轮第 N 张），thread 每轮新建即重置，数据库不存编号。两个后果在 2026-10-23 调优轮（会话 c1792718195836sp58）同时爆雷：①相关性分析卡先跑占了 card_1，四组回测成为 card_2~card_5，模型按"第 N 组方案 = card_N"心算写下 card_4，实际展示第 3 组 rank20（+23.8%），文本声称的最优 IC 加权组（+39.8%）从未展示，错误随消息落库固化；②多组回测只有被选中的一张落库，其余四组的完整结果（曲线/交易/持仓）随轮次蒸发，调优证据链不可回看。

产品基线约束：客户为果仁网类条件选股用户，回测必须无偏可信——调优证据链不可回看与展示错位都直接伤害这一基线。既有约束："一次回复只展示一张卡"（2026-10-12 拍板，维持不变）。

## Decision

1. **编号升级为会话事实**：`(conversation_id, seq)` 唯一，card_N = 本会话第 N 次回测，永不重置、跨轮稳定；GLM 回执与展示标记均用此编号，prompt 禁止按组序推算。
2. **编号命名空间只归回测**：分析类卡（rank_analysis/correlation）不占号、不入册、不参与【展示卡片】择优（展示走 card 通道 last-write 默认）。
3. **回测完成即入册**：新增 backtest_runs 表（元数据列 + card 全量 JSON），回测成功即落库（先于模型择优），未展示的组同样保存。
4. **消息落库形态不变（双写）**：agent 消息 card 列照旧存被展示卡的完整对象；runs 表与消息列各一份，读取路径/前端/存量零改动。
5. **跨轮回看**：【展示卡片：card_N】按 (conversation_id, seq) 解析，允许引用历史轮次的回测卡；prompt 约束仅用户要求回看时引用非本轮编号。
6. **删除级联与迁移**：删会话级联删该会话全部 runs；存量 backtest 卡一次性迁移入 runs 补 seq（分析类/旧 stocks/report 不迁）。

## Considered Options

- **仅加 prompt 硬约束（原样引用回执编号）**：不采——本次事故模型正是在推算而非抄写，纯约束治标；且编号占号陷阱仍在。
- **消息 card 列改存引用（单份存储）**：不采（列为后续升级）——需改读取路径、前端联动与存量迁移，而本次需求是"多保存"非"改存储"；双写以 30KB 级冗余换取零改动兼容。
- **分析卡也入册发号**：不采——编号命名空间再次不纯，"第 N 次回测"语义被稀释，重蹈错位覆辙。
- **维持回合内编号 + 轮末重置**：不采——跨轮回看（用户拍板"只要有记忆就可以看"）无法成立。

## Consequences

- "第 N 次回测 = card_N"成为恒等式，模型心算与回执编号天然一致，错位类事故机制性消除。
- 调优证据链完整可回看：每组回测（含未展示组）可在会话存活期内按编号随时重放展示。
- 展示卡在 runs 与消息列双份存储（30KB 级/张），接受。
- 历史事故丢失的结果不可恢复，只能重跑重建。
- 编号跨轮可见后，模型引用历史卡的行为需要 prompt 场景约束兜底。
