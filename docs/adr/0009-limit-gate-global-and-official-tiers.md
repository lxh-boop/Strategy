# ADR-0009：涨跌停判定全局收口、默认开启与官方分档价

Status: accepted（2026-10-22 grill 定案；同日已实施：全量 283 测试绿、真库冒烟通过）

## Context

ADR-0008 把涨跌停顺延参数化为 `limitUpDownSkip`（默认 false=掘金对齐），但只改了主引擎的三处调用点：b1 调仓卖出仍无条件躲跌停、b3 调仓补仓/减持完全无判定、触发引擎三处无条件判且无参数——9 处调用点三种状态并存，默认行为也不是完整的掘金对齐。判定口径为 ±9.99% 比率容差，低价股（真实涨停价因分币舍入涨幅 <9.99%）与 ST ±5% 档系统性误放行。用户定调：涨跌停要做成**全引擎一个总开关，直接决定所有买卖**，且分档规则（ST ±5%、创业板/科创板 ±20%）要做。

事实基础（2026-10-22 实连库验证）：掘金侧策略（goldminer main.py）仅市价单、无任何涨跌停处理；库内存在官方涨跌停价表 `mkt_limit`（1,937 万行，2007-2026，全市场覆盖），官方价天然涵盖主板 ±10% / ST ±5% / 创业板·科创板 ±20% / 北交所 ±30% 与新股特殊段，抽查分档全部命中；`mkt_equd` 原始昨收与 `mkt_limit.PRE_CLOSE_PRICE` 逐分一致，前复权换算链成立（同日调整因子唯一）。

## Decision

1. **默认翻转**：`limitUpDownSkip` 缺省改为 **true**——修订 ADR-0008 的默认值决定。理由：真实度优先；掘金对照降级为显式操作（引擎传 false，对照口径靠参数对齐而非默认口径）。开关形态仍是布尔、名字不变，语义升级为"全引擎唯一涨跌停开关"。
2. **判定收口 Account**：涨跌停判定下沉进 Account 执行原语（buy/sell/sellAll/rebalanceToTotal），删除全部 9 处调用点散判定——结构性保证今后新增买卖路径自动过闸（b3 漏判类事故不可能再发生）。
3. **触发引擎同参同实现**：trigger spec 加同名参数，与主引擎共享收口，消除两引擎语义劈叉。
4. **官方价路线**：档位不自算——readQuoteSeries JOIN `mkt_limit`（官方涨停/跌停价）与 `mkt_equd`（原始昨收），按同日调整因子换算到前复权口径比较。缺行（<0.1%）降级为该笔不判并计数进摘要。
5. **不做**：创业板 2020-08-24 制度切换（官方价天然正确，且当前不用早期数据）；新股上市初期特殊段（官方价即真实段价格）；ST 事件表覆盖修正（equ_inst_sstate，列为 v1.1 可选——已知残留：600363 实施 ST 三周后官方表仍 ±10%）。

## Considered Options

- **保持 ADR-0008 默认 false（默认口径=对照口径）**：否决（用户拍板）——打磨期进入真实度优先阶段，默认开启；对照模式显式传参，两侧对齐记录在案（掘金侧无涨跌停逻辑，引擎关即对齐）。
- **引擎内推导档位**（板块 ticker+exchange 推 + equ_inst_sstate ST PIT + 自算 round + 自维护日历）：否决——管线长（ST PIT、白名单错位 tables.md md_company_status→equ_inst_sstate）、rounding 与制度切换自担；官方价即交易所口径。
- **比率容差分档**（9.99/4.99/19.99/29.99）：否决——低价股与 ST 档舍入误差占比翻倍，官方价路线下问题不存在。
- **无条件判、不设开关**：否决——ADR-0008 已定的对照验收标准（与主流平台可互证）需要"能整体关掉"。

## Consequences

- 默认跑的回测结果与 2026-10-22 之前不可比（b1/b3/触发引擎行为从"部分不判"变为"全判"；b1 关闭时从"无条件躲跌停"变为"照常成交"）。
- 掘金对照的口径对齐从"默认即对齐"变为"显式传 false"。
- 引擎行情取数多两个 LEFT JOIN；QuoteRow 增加 limitUp/limitDown。
- 已知残留：官方源 ST 变更同步滞后（600363 案例）；缺行降级计数须在摘要可见。
