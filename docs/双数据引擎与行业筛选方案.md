> 版本 v2（2026-10-20）· 状态:**已评审定案，实施中（v2 最小集首批）**

> 依据:ADR-0004《双数据引擎：字典即路由与来源无感》、GLOSSARY.md「数据引擎」词条簇、Tushare 申万数据实测下载（SQL/industry/，2026-10-17）、SQL/industry/ 字典六件套（tables.md + 5 张字段 md，已按白名单格式撰写）。
> 前置确认（grill 已拍板，2026-10-17）:① 引擎 B 用 **DuckDB**（可自动转 parquet、**必须支持用户直接放 CSV**）；② 多引擎数据**互补不竞争**，设注册保险处理冲突；③ 无感 = **来源无感**（模型可点名数据，分不清出处），非内容无感；④ 行业筛选一步到位 **PIT**（current+historical 合并）；⑤ 数据文件与库文件不入 git，字典 md 入库；⑥ 不导入公共 MySQL、不常驻内存。

## 1. 背景与目标

### 1.1 现状

- 数据侧唯一引擎 = `MysqlFactorDataService`（core.module.ts:37 装配），连 herms_data@192.168.0.17，账号 `cht_readonly` **只读**——Tushare 数据进不去

### 1.2 目标

1. 双引擎并存:引擎 A = 公共 MySQL（不动），引擎 B = DuckDB 文件库（行业/板块 + 将来的用户私密数据）
2. 行业筛选:`run_strategy_backtest` 加 `industries` 参数，PIT 口径一步到位，引擎内核零改动
3. 用户自助放置私密数据:CSV 放目录 + 字典 md 即注册，注册保险拦截冲突
4. 来源无感:统一数据目录注入模型，展示层零来源标记

### 1.3 改造后新增能力（之前没有的）

| # | 用户能做的事 | 之前 | 之后 |
|---|---|---|---|
| 1 | "食品饮料+电力设备回测三年" | 无行业概念，只能全市场 | 申万一级任意组合筛池，PIT 归属 |

## 2. 设计原则（定死）

1. **字典即路由**:表登记在哪个字典就从哪个引擎取；任何查询只打一个引擎，跨引擎合并查询不存在——冲突被分工结构性消解，不做合并算法
2. **来源无感**:统一目录注入模型；卡片、确认门、日志等一切展示层不出现"私密/引擎/Tushare/来源"字样
3. **引擎内核零改动**:行业筛选在工具编排层解析成 `securityIds`，走现成通道
4. **不导入公共库、不常驻内存**:引擎 B 数据落 DuckDB 文件，随目录注册，可增量刷新
5. **注册保险前置**:重叠检查在注册时做，不在查询时做

## 3. 数据层:引擎 B（DuckDB）

### 3.1 存储与目录

| 项 | 值 | git |
|---|---|---|
| 引擎 B 库文件 | `factor-agent-server/SQL/industry/industry.duckdb` | 不入库（gitignore） |
| 首批导入源 | `SQL/industry/sw_member_current.csv`、`sw_member_historical.csv` | 已在仓库（Tushare 下载产物） |

**目录约定（2026-10-20 用户拍板）**：数据库相关文件统一放 `SQL/` 下对应数据集目录（本批 = `SQL/industry/`），**不新建** `data/private`、`SQL/private` 等新目录；第二批私密数据的目录设计届时按同一约定收敛（字典与数据同目录，数据文件 gitignore）。

### 3.2 首批表集（申万成分）

| 表 | 来源文件 | 唯一键 | 用途 |
|---|---|---|---|
| `sw_member` | current + historical 合并（is_new 列保留） | ts_code,in_date,out_date | PIT 行业归属查询 |
| `sw_classify` | sw2021_classify.csv | index_code | 行业名录（工具 schema 的 industries 枚举来源）、层级挂接 |

导入方式:引擎 B 初始化时若库文件缺失/源文件更新（按 mtime）则从 CSV 重建；用户放置新 CSV 的注册流程见 §5。

### 3.3 PIT 行业归属查询

```sql
-- resolve(industries[], asOfDate) → securityId[]
SELECT DISTINCT m.ts_code
FROM sw_member m JOIN sw_classify c ON c.index_code = m.l1_code
WHERE c.industry_name IN (?, ?)
  AND m.in_date <= ? AND (m.out_date IS NULL OR m.out_date >= ?)
```

- 后缀映射:`.SH → .XSHG`、`.SZ → .XSHE`（引擎 A 的 securityId 口径）；`.BJ` 首期不映射（北交所不在因子表覆盖内，命中即丢弃并计数）
- 行业名不在 L1 名录（31 个）→ `ClarificationSignal` 引导澄清（与现有缺参语义一致）

## 4. 引擎抽象与路由

1. core 新增 `DataEngine` 契约（本期只落两个方法面:`resolveIndustryMembers`（引擎 B 独有）、引擎探活/目录贡献；因子截面仍由引擎 A 的 `FactorDataService` 承载，不强行虚化）
2. 路由 = **字典归属**（v2 落地范围）:表在 `SQL/tables.md` → 引擎 A；在 `SQL/industry/tables.md` → 引擎 B。`assertWhitelist` 与表目录注入改为两套字典并集；**GLM 查行业表复用既有 read_factor_data 工具**（路由发生在工具执行层，GLM 无感）。`SQL/private`（私密目录）与注册保险延后第二批，落地后同一机制扩一路
3. 取数并行:回测编排层对 A/B 的请求 `Promise.all`（行业集合与因子截面互不依赖）
4. 引擎 A 归位:类名不改（避免无谓 diff），在 core.module 注释标注"引擎 A（公共库）"

## 5. 注册流程与保险

```
用户放 CSV 到 data/private/ + 写 SQL/private/<表名>.md
  → 引擎 B 注册器发现（启动扫描 + 文件变化重扫）
  → 按字典 md 的字段清单校验 CSV 表头
  → 注册保险:
      表名与公开/私有既有表重名 → 硬拦（报冲突清单）
      唯一键与既有表相同 → 硬拦
      仅业务域重叠（表名不同）→ 放行 + 启动输出软告
  → 入库（直读 CSV 视图，或用户声明物化时转 parquet）
  → 表目录进入统一注入清单（无来源标记）
```

## 6. 参数接口与编排层

`run_strategy_backtest` 新增:

```
industries?: string[]   // 申万一级行业名；缺省 = 不筛行业（数量不设上限，31 个全量合法）
```

- 执行序:校验 industries ∈ L1 名录（否则 ClarificationSignal）→ PIT 解析 securityIds → 与显式 securityIds 取交集（都传时）→ 走现有通道
- 确认门:确认文案由 formatConfirmText 追加一行「行业筛选:食品饮料、电力设备（候选 N 只）」
- 卡片:params 由引擎产出透传，自动带「行业筛选」项——**编排层不拼来源字样**（来源无感约束）
- **每日选股对称**（v2）:run_daily_screen 同步加 `industries`，同一 resolve 管线——回测与每日选股的行业口径永不漂移
